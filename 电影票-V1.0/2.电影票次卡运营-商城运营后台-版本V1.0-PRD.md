# 电影票次卡运营后台 PRD（基于原型）

## 1. 文档信息
- 产品名称：电影票次卡运营后台
- 模块范围：次卡管理（批次管理、批次创建、批次明细、批量操作）
- 文档版本：v1.0（原型解析版）
- 目标读者：产品、研发、测试、运营
- 原型来源：`movie-ticket-card-prototype.html`

---

## 2. 背景与问题定义

当前电影票次卡业务需要一个统一的运营后台，支持从“批次创建 -> 批次发放 -> 明细查询 -> 激活/作废 -> 导出/批处理”完整链路管理。  
现有问题是批次与单卡明细管理分散，操作效率低、状态不一致风险高、导出与批量处理能力不足，难以支撑高频运营活动。

---

## 3. 目标与成功指标

### 3.1 产品目标
1. 提供标准化的次卡批次管理流程，降低人工操作成本。
2. 提供明细级状态管控（未激活/已激活/作废）与可追溯能力。
3. 提供批量激活/作废与导出能力，提升大促/活动期运营效率。
4. 保证关键敏感信息（次卡密钥）可控展示与可选导出。

### 3.2 成功指标（建议）
- 批次创建平均耗时：< 2 分钟
- 单次明细查询响应：< 1 秒（1000 条内）
- 批量操作（1000 条）提交成功率：>= 99.9%
- 导出成功率：>= 99.9%
- 误操作回退（通过确认弹窗拦截）：拦截率 >= 95%

---

## 4. 用户角色与使用场景

### 4.1 角色
- 运营专员：日常创建批次、激活/作废、查询、导出
- 运营主管：审核结果、复盘活动效果、处理批量任务

### 4.2 核心场景
1. 新活动上线前创建批次并配置有效期、面值规则。
2. 按批次追踪单卡使用与兑换进度。
3. 针对特定明细做激活/作废处置。
4. 按筛选条件导出明细（可选含/不含卡密）。
5. 使用模板批量激活或批量作废。

---

## 5. 页面与信息架构

### 5.1 页面说明
- 批次管理页：批次列表、筛选、分页、单批次操作入口
- 新增批次页：基本信息、次卡规格、有效期配置
- 批次列表明细页：明细筛选、状态流转、查看详情、导出、批量入口
- 批量操作页：三步向导（下载模板 -> 上传数据 -> 完成）
- 弹窗：详情弹窗、确认弹窗、卡密弹窗、导出弹窗

### 5.2 页面路径
- 首页 -> 次卡管理 -> 批次管理
- 批次管理 -> 新增批次
- 批次管理 -> 批次明细 / 使用情况
- 批次列表明细 -> 批量操作
- 批次列表明细 -> 导出弹窗 / 卡密弹窗 / 详情弹窗

## 6. 功能需求（FRD）

### 6.1 批次管理页

#### 查询条件
| 功能/字段名称 | 交互逻辑 | 数据逻辑（性能要求） | 业务逻辑 |
|---|---|---|---|
| 批次号 | 输入关键字后查询 | 支持模糊匹配；1000 条内秒级返回 | 用于精准定位批次 |
| 批次名称 | 输入关键字后查询 | 同上 | 支持活动命名检索 |
| 状态 | 全部/正常/作废 | 枚举筛选 | 控制运营查看范围 |
| 面值 | 输入金额筛选 | 数值匹配 | 对应规格筛选 |
| 单次使用上限金额 | 输入金额筛选 | 数值匹配 | 风控相关筛选 |
| 客户名称 | 关键字筛选 | 文本匹配 | B 端客户检索 |
| 渠道名称 | 关键字筛选 | 文本匹配 | 渠道对账 |
| 有效期时间 | 起止时间筛选 | 时间区间过滤 | 有效卡池管理 |

#### 列表字段
批次号、批次名称、面值、次数、数量、单次使用上限金额、客户名称、渠道名称、有效期时间、状态、操作。

#### 列表操作
- `批次明细`：跳转并带入批次号筛选
- `作废`：弹窗二次确认后置为作废；若该批次号下存在已激活明细，则提示“不能作废该批次，请到批次列表明细页操作”
- `新增批次卡`：跳转创建页

#### 批次号生成规则
- 规则：`[业务类型][年份时间]-[序列号]`，示例：`DYP20260414-001`
- 序列号默认 3 位，从 `000` 递增至 `999`
- 超过 `999` 后自动补 4 位及以上，按数值连续递增（动态补充位数）

#### 排序与分页
- 分页：上一页/下一页/跳页/每页条数（2/5/10/20）
- 默认每页 5 条（原型行为）

### 6.2 新增批次页

#### 字段与规则
| 字段 | 必填 | 规则 | 说明 |
|---|---|---|---|
| 批次号 | 是 | 自动生成，格式 `[业务类型][年份时间]-[序列号]`，示例 `DYP20260414-001`；序列号默认 3 位（`000-999`），超出后自动扩展为 4 位及以上（动态补充位数） | 只读 |
| 批次名称 | 是 | 文本输入 | 业务命名 |
| 客户名称 | 否 | 文本输入 | 客户标识 |
| 渠道名称 | 是 | 下拉选择 | 渠道归属 |
| 备注 | 否 | 文本输入 | 运营备注 |
| 次数 | 是 | 数值 >=1 | 次卡总次数 |
| 单次使用上限金额 | 是 | 数值 >=1 | 单次消费封顶 |
| 面值 | 是 | 自动计算：次数 * 单次上限 | 只读 |
| 数量 | 是 | 数值输入 | 发卡张数 |
| 有效期起始/截止 | 是 | datetime-local | 支持快捷设置 |
| 快捷设置 | 否 | 近7/30/90/180天 | 自动填充有效期 |

#### 提交行为
- 点击“提交批次”后返回批次管理页（原型中为前端模拟）
- “取消”返回批次管理页

### 6.3 批次列表明细页

#### 查询条件
| 功能/字段名称 | 交互逻辑 | 数据逻辑（性能要求） | 业务逻辑 |
|---|---|---|---|
| 批次号 | 输入后筛选 | 支持 includes 匹配；批次号生成规则为 `[业务类型][年份时间]-[序列号]`，示例 `DYP20260414-001`；序列号默认 3 位（`000-999`），超出后自动扩展为 4 位及以上（动态补充位数） | 批次维度定位 |
| 批次名称 | 输入后筛选 | 文本匹配 | 活动维度定位 |
| 批次明细编号 | 输入后筛选 | 文本匹配；生成规则为 `批次号-序列号`，即 `([业务类型][年份时间]-[序列号])-[明细序列]`。明细序列默认 3 位，从 `000` 到 `999`；若位数不够则动态扩展为 4 位及以上。示例：`DYP20260414-001-001` | 单卡定位 |
| 使用人账号 | 输入后筛选 | 文本匹配 | 用户追踪 |
| 使用人手机号 | 输入后筛选 | 文本匹配 | 客诉核验 |
| 状态 | 全部/已激活/未激活/作废 | 枚举过滤 | 运营处置 |

#### 列表字段
勾选框、批次号、批次名称、批次明细编号、状态、面值、单次使用上限金额、兑换状态、使用次数/总次数、渠道名称、有效期、使用人账号、使用人手机号、激活时间、次卡激活操作人、操作。

#### 状态与业务规则
- 状态：`未激活` / `已激活` / `作废`
- 兑换状态推导：已使用次数 > 0 => 已兑换，否则未兑换
- 激活时自动补齐：激活时间（当前时间）、激活操作人（运营系统，若为空）
- 作废状态不可再激活（批量时会过滤不可操作项）

#### 单条操作
- `激活`：仅未激活可执行，需确认弹窗
- `作废`：除“作废”状态外均可执行，需确认弹窗；作废成功后操作栏仅保留“详情”按钮
- `详情`：打开“次卡使用情况详情”弹窗，展示使用记录
- `查看次卡密钥`：展示卡密并支持复制（部分状态可见）；次卡密钥生成规则为 8 位，字符集由数字 `2-9`（排除 `0`、`1`）与大写字母 `A-Z`（排除 `I`、`O`）组成，示例：`ZFYX9988`

#### 批量操作入口
- 批量激活
- 批量作废  
> 对勾选数据做可执行校验，确认弹窗展示“总勾选数、可操作数、不可操作提示”。

#### 导出
- 导出模式：  
  - 导出选中数据  
  - 导出所有筛选数据
- 导出字段：默认导出列表行所有字段（与当前列表展示字段一致）
- 导出内容模式：  
  - 不含次卡密钥  
  - 包含次卡密钥
- 导出类型与密钥列关系：当选择“包含次卡密钥”时，在导出结果中新增“次卡密钥”列；选择“不含次卡密钥”时不增加该列
- 导出格式：CSV（UTF-8 BOM）

#### 分页
- 上一页/下一页/跳页/每页条数（5/10/20）
- 筛选后重置到第一页

### 6.4 批量操作页（向导）

#### 入口与模式
- 从明细页“批量操作”进入
- 模式：`批量激活` / `批量作废`

#### 三步流程
1. 下载导入模板  
2. 上传数据（支持 `.xlsx/.xls`，单文件 <=2MB，支持多文件）  
3. 完成（展示“已提交”结果）

#### 模板涉及字段
- 批量激活与批量作废共用模板字段：`批次号`、`批次名称`、`批次明细编号`、`状态`
- `状态` 字段可选值：`激活`、`作废`

#### 约束文案
- 每次最多导入 1000 条
- 批量激活：可不填激活时间，默认当前时刻
- 批量作废：作废后不可恢复，谨慎操作

## 7. 非功能需求（NFR）

- 安全：
  - 卡密默认不在列表直接暴露
  - 导出卡密需显式二次选择
- 可用性：
  - 高风险操作均需确认弹窗
  - 重要按钮状态清晰（可点/禁用）
- 性能：
  - 列表查询、筛选、翻页操作流畅（1000 条内）
- 可追溯：
  - 激活时间、激活操作人必须可回溯
- 可维护：
  - 状态流转规则统一，避免前后端口径不一致

## 9. 权限与风控（建议）
- 查看卡密：需具备“卡密查看权限”
- 导出含卡密：需具备“敏感导出权限”，并记录审计日志
- 批量作废：建议仅主管角色可执行
- 所有状态变更需写操作日志（操作者、时间、对象、前后状态）

## 10. 埋点与日志（建议）
- 查询行为：筛选条件、结果数、耗时
- 状态操作：激活/作废（单条、批量）
- 导出行为：模式（选中/筛选）、是否含卡密、导出条数
- 卡密操作：查看、复制
- 错误日志：导出失败、批量导入失败、状态变更失败

## 11. 依赖与风险

### 依赖
- 卡密服务（生成、展示、权限校验）
- 导出服务（CSV 生成）
- 批量导入服务（模板解析、校验、异步处理）
- 账号权限系统（RBAC）

### 风险
- 前后端状态枚举不一致导致筛选异常
- 批量作废误操作造成业务损失
- 卡密泄露风险（导出、复制环节）
- 大批量导出可能导致性能抖动

### 风险缓解
- 统一状态字典与契约测试
- 二次确认 + 权限分级 + 操作审计
- 敏感字段脱敏与审批导出
- 导出异步化 + 文件中心下载

## 12. 范围定义

### In Scope（本期）
- 批次管理、批次创建、批次明细查询
- 单条/批量激活作废
- 明细导出（含/不含卡密）
- 详情弹窗与卡密查看复制

### Out of Scope（本期不做）
- 真正的后端接口与数据库落地细节
- 多租户隔离策略细节
- 卡密加解密算法细节

### Future（后续迭代）
- 批量任务异步队列与进度中心
- 更细粒度审批流（例如作废审批）
- 高级报表（渠道、客户、活动维度）

## 13. 验收标准（UAT）

1. 能成功创建批次，且面值自动计算正确。  
2. 批次列表支持按条件筛选与分页。  
3. 明细列表支持多条件筛选，状态筛选准确。  
4. 单条激活/作废后状态与操作按钮正确刷新。  
5. 批量激活/作废仅处理可处理数据，提示信息准确。  
6. 导出选中/筛选数据均可成功下载。  
7. 导出“含卡密/不含卡密”字段差异正确。  
8. 卡密复制成功时有提示，失败时有降级提示。
