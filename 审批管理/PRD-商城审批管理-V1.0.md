## 一、版本概述

商城审批管理覆盖审批列表页与审批详情页两个核心页面，实现 6 种审批类型的只读镜像展示。本系统不承载审批操作，所有审批流转均在简道云完成，本系统负责拉取审批数据并按统一框架展示。

### 1.1 页面清单

本次 PRD 覆盖以下页面：

| 页面 | 文件路径 | 层级 |
|------|----------|------|
| 审批列表页 | 审批管理-原型.html（#page-list） | 一级 |
| 审批详情页 | 审批管理-原型.html（#page-detail） | 二级 |

共 2 个页面。

### 1.2 核心功能

本系统以"只读镜像"方式展示简道云中的审批流程，覆盖 6 种审批类型：A2 指定供应商审核（简道云已建流程镜像）、B5 品牌商城入驻申请（新建，business_context 原样镜像展示）、B1 亏损特批申请、B2 新建卡券模板、B3 平台代发卡券/积分、B4 售后补偿发放（以上四组为简道云新建流程，镜像页聚合展示）。用户可在列表页切换"管理员/我的"视角、按工作台 Tab（待我审/我发起的/已完成等）聚合，再叠加状态、类型、时间筛选与单号/申请人搜索定位审批，点击卡片进入详情查看业务信息与各审批节点。

### 1.3 数据来源说明

| 数据类型 | 来源 | 说明 |
|----------|------|------|
| 审批主数据 | 简道云审批列表 API | 审批单号、类型、状态、申请人、提交时间等主字段 |
| 审批节点数据 | 简道云审批详情 API | 节点名称、审批人、审批时间、审批意见 |
| 业务字段 | 简道云 business_context（JSON） | 按类型动态存储的业务上下文 |
| 模板详情 | 卡券模板表（后端查询） | 简道云关联字段仅返回模板名，子字段需后端按模板 ID 反查 |
| 计算字段 | 后端计算 | 消耗积分、剩余积分等系统计算值 |

### 1.4 统计口径

审批状态枚举（5 种）：

| 状态标识 | 状态名称 | 含义 |
|---------|---------|------|
| PENDING | 审批中 | 流程进行中，存在未完成节点 |
| APPROVED | 已通过 | 所有节点通过，流程结束 |
| REJECTED | 已驳回 | 某节点驳回，流程结束 |
| WITHDRAWN | 已撤回 | 申请人主动撤回，流程结束 |
| TERMINATED | 已终止 | 系统或管理员强制终止，流程结束 |

> 其中已撤回（WITHDRAWN）、已终止（TERMINATED）两种状态当前版本筛选栏不提供独立筛选选项（详见 2.1.6，筛选仅含全部/审批中/已通过/已驳回），这两种状态的审批单仅可在"全部"中查看，详情页时间线仍按对应状态渲染。

审批类型枚举（6 种）：

| 类型标识 | 类型名称 | 简道云状态 |
|---------|---------|-----------|
| A2 | 指定供应商审核 | 已建（镜像） |
| B1 | 亏损特批申请 | 新建 |
| B2 | 新建卡券模板 | 新建 |
| B3 | 平台代发卡券/积分 | 新建 |
| B4 | 售后补偿发放 | 新建 |
| B5 | 品牌商城入驻申请 | 新建（镜像展示） |

## 二、审批管理

本模块包含审批列表页与审批详情页，承载所有审批类型的查看功能。

### 2.1 审批列表页（approval-list）

审批列表页是用户进入审批管理的首屏，以卡片形式聚合展示所有审批单，支持按状态与类型快速筛选。

#### 2.1.1 功能概述

列表页展示当前账号可见的全部审批单，每条审批以卡片形式呈现类型、状态、业务摘要、编号、申请人、提交时间、当前审批环节七个核心字段。页面顶部提供状态切换按钮（全部/审批中/已通过/已驳回）与类型筛选，帮助用户快速定位目标审批。

#### 2.1.2 界面设计

页面自上而下分三层：顶部「视角切换器 + 工作台 Tab」、其下「筛选区（类型/状态/时间胶囊 + 单号/申请人搜索）」、「卡片列表区」。视角切换器决定工作台 Tab 的聚合维度与"全部"范围（详见 2.1.8）；筛选区在 Tab 选定范围内再做字段过滤，二者为 AND 关系。卡片列表区纵向排列，每张卡片右侧带"查看 →"引导。

| 区域 | 元素 | 说明 |
|------|------|------|
| 顶部 | 标题"审批管理" | 页面标题 |
| 顶部 | 视角切换器 | 管理员视角 / 我的视角，右侧显示当前角色名（详见 2.1.8） |
| 顶部 | 工作台 Tab | 随视角变化：管理员（全部/待我审/我发起的/已完成）、我的（全部/待我审批/我发起的/我已审批） |
| 筛选区 | 类型胶囊 | 全部 / A2 / B1 / B2 / B3 / B4 / B5 |
| 筛选区 | 状态胶囊 | 全部 / 审批中 / 已通过 / 已驳回（详见 2.1.6） |
| 筛选区 | 时间胶囊 + 搜索框 | 时间区间、单号/申请人搜索（详见 2.1.6） |
| 列表区 | 审批卡片 | 每条审批一张卡片 |
| 卡片 | 查看引导 | 右侧"查看 →" |

#### 2.1.3 操作流程

```mermaid
flowchart TB
    Start([用户进入]) --> Render["渲染审批卡片列表"]
    Render --> Filter{是否筛选?}
    Filter -->|是| Select["选择状态/类型"] --> Render
    Filter -->|否| Click{点击卡片?}
    Click -->|是| Detail["进入详情页"]
    Click -->|否| End([停留列表)
```

点击卡片调用 `showDetail(id)` 进入详情页。

#### 2.1.4 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| RULE-LIST-001 | 列表默认展示全部状态、全部类型，按提交时间倒序排列 |
| RULE-LIST-002 | 状态切换即时刷新列表，不产生新请求 |
| RULE-LIST-003 | 卡片在类型标题与元信息之间展示一行业务摘要，按类型提取关键字段拼接，非空时展示 |

#### 2.1.5 字段与交互

卡片统一展示以下 6 个基础字段（所有审批类型一致），并在类型标题与元信息之间额外展示一行业务摘要：

| 字段名称 | 字段标识 | 数据类型 | 数据来源 | 展示规则 | 示例 |
|---------|---------|---------|---------|---------|------|
| 审批类型 | type | Enum | type 字段 | 显示类型中文名 | 指定供应商审核 |
| 审批状态 | status | Enum | status 字段 | 显示状态中文+对应颜色标签 | 审批中（蓝） |
| 审批单号 | id | String | id 字段 | 原样展示 | AP20260720001 |
| 申请人 | applicant | String | applicant 字段 | 原样展示 | 陈浩 |
| 提交时间 | time | String | time 字段 | 原样展示 | 2026-07-20 10:00 |
| 当前审批环节 | approver | String | 当前 doing 节点的 approver | 仅审批中显示，展示当前审核人姓名 | 周敏 |

卡片在类型标题与元信息之间额外展示一行业务摘要，按审批类型提取关键业务字段拼接，帮助用户在列表页快速区分同类型审批。摘要仅在非空时展示，提取规则如下：

| 类型 | 提取字段 | 拼接规则 | 示例 |
|------|---------|---------|------|
| A2 | 商品SPU名称 | 从 biz 数组中提取 | 测试品牌_1527 |
| B1 | 商品SKU名称 + 关联渠道 | 用“ · ”连接 | 3M口罩 {白,常规} · 企业购 |
| B2 | 模板名称 | 从 biz 数组中提取 | 新人专享满99减20 |
| B3 | 品牌商城 + 发放数量 | 品牌商城 + " · 发放 " + 数量 | 某品牌A商城（ID·A001） · 发放 1,200 张 |
| B4 | 品牌商城 + 卡券名称 | 用" · "连接 | 某品牌A商城 · 质量问题补偿券·8月 |
| B5 | 品牌商城名称 | 从 biz.supplier 企业认证分组提取 | 某品牌A商城 |

#### 2.1.6 筛选与搜索

列表页提供筛选区与独立字段搜索区，筛选为胶囊单选、搜索为多输入框显式触发，二者为 AND 关系。

**筛选维度（胶囊单选，每组互斥，含"全部"默认项）：**

| 筛选项 | 可选值 | 规则 |
|--------|--------|------|
| 类型 | 全部 / A2 / B1 / B2 / B3 / B4 / B5 | 选中后过滤 type 字段 |
| 状态 | 全部 / 审批中 / 已通过 / 已驳回 | 选中后过滤 status 字段 |
| 时间 | 全部 / 近 7 天 / 近 30 天 / 近 90 天 / 自定义 | 近 N 天以当天 00:00 为基准动态计算；自定义展示开始/结束两个日期输入框，支持区间（含两端） |

**搜索维度（2 个独立输入框，分别匹配单一数据源，不做跨字段拼接）：**

| 搜索框 | 标识 | 匹配数据源 | 匹配方式 | 示例 |
|--------|------|-----------|---------|------|
| 审批单号 | f-id | id 字段 | 模糊（包含） | 输入"18008"可命中 AP20260718008 |
| 申请人 | f-applicant | applicant 字段 | 模糊（包含） | 输入"道馨"可命中相关记录 |

> **不提供业务关键词搜索**：审批的业务明细字段（如商品名、模板名、商城名、企业名称、供货价等）结构因类型而异、且含动态 JSON，做跨字段关键词搜索开发成本高、命中噪声大，本期不提供该能力。用户定位审批的途径为：审批单号 / 申请人 + 类型 / 状态 / 时间 筛选。如需按业务明细字段检索，后续迭代可通过「按类型动态展开的结构化筛选项」或「导出明细」解决。

搜索采用**显式触发**：点击「查询」按钮或按回车键后执行，不支持输入即搜。多个搜索框之间为 AND 关系，可同时填写。筛选项激活会实时更新底部"已选 N 项筛选"计数，搜索框填写后需点击查询才计入计数。

**重置：** 点击「重置」清空所有筛选胶囊、搜索框、日期区间，列表恢复默认。

#### 2.1.7 页面跳转

| 触发 | 去向 |
|------|------|
| 点击卡片 | 审批详情页（showDetail） |

#### 2.1.8 视角与工作台 Tab

列表页顶部提供「视角切换器」，两个视角按"维度"分工、互不重叠：管理员视角做全局状态监控、我的视角做个人工作台。切换后工作台 Tab、计数与筛选区可见性随之变化。视角只改变聚合维度与可见范围，不改变卡片字段。

| 视角 | 适用角色 | 工作 Tab | 数据范围 |
|------|---------|---------|---------|
| 管理员视角 | 管理员（纯运维监控，不参与审批/发起） | 全部 / 审批中 / 已通过 / 已驳回 | 全员全量，按状态聚合 |
| 我的视角 | 运营专员（参与审批/发起） | 全部 / 待我审批 / 我发起的 / 我已审批 | 仅与我相关，按"我与审批的关系"聚合 |

各 Tab 取数口径：

| Tab | 视角 | 取数规则 |
|-----|------|---------|
| 全部 | 管理员 | 全量审批（全员） |
| 审批中 | 管理员 | status=PENDING |
| 已通过 | 管理员 | status=APPROVED |
| 已驳回 | 管理员 | status=REJECTED |
| 全部 | 我的 | isRelatedToMe：applicantSelf，或 (status=PENDING 且 approverCurrent=当前用户)，或被当前用户审过 |
| 待我审批 | 我的 | status=PENDING 且 approverCurrent=当前用户 |
| 我发起的 | 我的 | applicantSelf=true |
| 我已审批 | 我的 | 节点中 approver=当前用户 且节点状态∈{pass, refuse} |

> 管理员视角的 Tab 已是状态维度，故该视角下**隐藏状态筛选胶囊**（避免重复），只保留类型/时间/搜索框；切到「我的视角」后状态胶囊恢复显示。视角切换会重置 Tab 至该视角首个、清空筛选、回到第 1 页。Tab 计数实时显示在 Tab 文案后的胶囊中，切 Tab 即时刷新、不产生新请求。Tab 与筛选区为 AND 关系。

| 规则编号 | 规则描述 |
|---------|---------|
| RULE-VIEW-001 | 视角切换器位于列表页顶部，默认"管理员视角"，右侧显示当前角色名 |
| RULE-VIEW-002 | 切换视角时重置 Tab 至该视角首个、清空筛选条件、列表回到第 1 页 |
| RULE-VIEW-003 | 工作 Tab 计数为实时统计，切 Tab 即时刷新列表、不产生新请求 |
| RULE-VIEW-004 | 管理员为纯监控角色，不参与审批与发起，其视角不含“待我审/我发起的”等个人维度 Tab；管理员视角下列表仅提供“查看”操作，无撤回/冻结等操作权限 |
| RULE-VIEW-005 | 管理员视角隐藏状态筛选胶囊（Tab 已覆盖状态维度），我的视角保留 |

### 2.2 审批详情页 - 通用框架（approval-detail）

审批详情页按审批类型动态渲染业务信息与节点信息，但所有类型共用同一套页面骨架。

#### 2.2.1 功能概述

详情页展示单条审批的完整信息，自上而下分为头部信息区、审批流程时间线、业务信息区、节点信息区四个部分。根据审批类型不同，业务信息区与节点信息区采用两种布局：B5 采用两栏布局（左品牌商城三认证 Tab、右节点信息 Tab），其他类型采用单栏布局（上业务信息面板、下节点信息 Tab）。

#### 2.2.2 界面设计

页面自上而下纵向排列四个区域。头部信息区展示标题、状态标签、单号、申请人、提交时间。时间线区以圆点+竖线形式展示各节点流转。业务信息区与节点信息区根据类型采用不同布局。

| 区域 | 元素 | 说明 |
|------|------|------|
| 头部 | 标题 | 审批类型中文名 |
| 头部 | 状态标签 | 对应颜色的状态标签 |
| 头部 | 单号/申请人/提交时间 | 三项主信息 |
| 时间线 | 节点圆点+竖线 | 各节点流转可视化 |
| 时间线 | 流程结束节点 | 末尾固定节点，按状态变色 |
| 业务信息 | 面板/Tab | 按类型渲染 |
| 节点信息 | Tab | 按类型渲染 |

#### 2.2.3 操作流程

```mermaid
flowchart TB
    Detail["进入详情页<br/>加载审批数据"] --> Type{类型判断}
    Type -->|B5| TwoCol["两栏布局<br/>左:品牌商城三认证Tab<br/>右:节点信息Tab"]
    Type -->|其他| Single["单栏布局<br/>上:业务信息面板<br/>下:节点信息Tab"]
    TwoCol --> Switch{切换Tab?}
    Single --> Switch
    Switch -->|是| ReRender["重渲染对应节点字段"]
    Switch -->|否| Back{返回列表?}
    ReRender --> Back
    Back -->|是| List["返回列表页"]
    Back -->|否| End([停留详情)
```

#### 2.2.4 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| RULE-DETAIL-001 | 节点信息 Tab 过滤"发起"节点，不作为独立 Tab 展示 |
| RULE-DETAIL-002 | 时间线末尾固定追加"流程结束"节点，所有类型一致 |
| RULE-DETAIL-003 | 流程结束节点圆点颜色随审批状态变化：PENDING 灰、APPROVED 绿、其余红 |
| RULE-DETAIL-004 | 节点 Tab 默认激活第一个节点，渲染其 refs（上游引用，灰底）与 fields（本节点填写，蓝边白底） |
| RULE-DETAIL-005 | 图片类型字段（标识为 img）独立渲染为图片占位块，不与其他文本字段混排 |
| RULE-DETAIL-006 | 时间线各节点（含审批中 doing）均展示审批人姓名，便于查看每个环节由谁负责 |
| RULE-DETAIL-007 | 详情页头部右侧显示“撤回”按钮，仅发起人本人且审批进行中可见；点击弹出撤回原因填写框，确认后流程终止 |

#### 2.2.5 字段与交互

详情页头部统一字段：

| 字段名称 | 字段标识 | 数据类型 | 数据来源 | 展示规则 | 示例 |
|---------|---------|---------|---------|---------|------|
| 审批标题 | d-title | String | 类型中文名 | 顶部主标题 | 指定供应商审核 |
| 状态标签 | d-status | String | status 映射 | 带颜色的标签 | 审批中（蓝） |
| 审批单号 | d-code | String | id | 单号行 | AP20260720001 |
| 申请人 | d-applicant | String | applicant | 单号行 | 陈浩 |
| 提交时间 | d-time | String | time | 单号行 | 2026-07-20 10:00 |

节点 Tab 字段分区：

| 分区 | 样式 | 数据来源 | 说明 |

### 2.3 审批流程通用规则

#### 2.3.1 审批链动态化（按发起人部门）

各类审批的审批链均为“特定流程”，但其中**“发起人直属领导”环节会根据发起人所在部门动态变化**：不同部门的发起人，其直属领导不同，对应的首审节点审批人也随之不同。其余环节（如科技事业部副总经理、财务经理等）为该类型固定的后续审批节点，不随发起人变化。

| 发起人所在部门 | 首审节点（发起人直属领导） | 审批人示例 |
|------|------|------|
| 运营中心 | 运营主管 | 泽梅 / 赵主管 |
| 商品中心 | 商品部经理 | 周敏 |
| 客服中心 | 客服主管 | 路宁 |
| 业务部门 | 业务主管 | （按实际组织架构配置） |

> 完整审批链 = 发起 → [发起人直属领导 · 动态] → 后续固定节点 → 流程结束。
> 例：A2 指定供应商审核由商品中心发起，链路为“发起 → 商品部经理（直属领导）→ 科技事业部副总经理 → 财务经理”；若改由运营中心同事发起，则首审节点变为“运营主管”，后续节点不变。

#### 2.3.2 节点与人名命名规范

为避免节点名与审批人信息重复，统一以下命名规则：

| 字段 | 命名规则 | 示例 |
|------|------|------|
| 节点名（node.name） | 统一用“职位 / 角色”，不带“审核”后缀 | 商品部经理、财务经理、科技事业部副总经理、运营主管、客服主管 |
| 审核人（node.approver） | 统一为纯姓名，不重复职位（职位已在节点名中体现） | 周敏、孙强、张明 |
| 申请人（applicant） | 统一为纯姓名 | 陈浩、道馨 |
| 当前待办人（approverCurrent） | 纯姓名，与当前 doing 节点的 approver 保持一致 | 周敏 |

#### 2.3.3 审批人展示规则

- 详情页时间线：每个节点（含审批中 doing）均展示审核人姓名（对应 RULE-DETAIL-006）。
- 列表页“当前审批环节”列：展示当前 doing 节点的审核人姓名，不展示环节名与“审批中”字样（详见 2.1.5）。

节点信息区（右栏）按简道云审批链流转（发起 → 财务经理 → …），各节点填写字段随节点变化，规则同 2.2 通用框架。

> B5 采用"三认证 + 两栏布局"的镜像展示，与 A2（指定供应商审核，单栏）区分；企业认证含「品牌商城名称 / 品牌商城ID / 销售模式」，财务认证含「财务渠道名称 / 财务结算编码」，为品牌商城入驻专属字段。

## 四、数据模型

### 4.1 approval_main 表（审批主表）

审批主表存储简道云同步过来的审批主数据，按审批单号唯一标识。

```json
{
  "id": "AP20260720001",
  "type": "A2",
  "status": "PENDING",
  "applicant": "陈浩",
  "time": "2026-07-20 10:00",
  "business_context": { },
  "nodes": [ ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 审批单号，主键 |
| type | Enum | 审批类型（A2/B1/B2/B3/B4/B5） |
| status | Enum | 审批状态（PENDING/APPROVED/REJECTED/WITHDRAWN/TERMINATED） |
| applicant | String | 申请人 |
| time | String | 提交时间 |
| business_context | JSON | 业务字段，按类型动态存储 |
| nodes | Array | 审批节点数组 |

### 4.2 business_context 结构（按类型）

business_context 按 type 不同存储不同字段，简道云新增字段时静默入库，不做强校验。

### 4.3 字段来源映射总表

| 镜像页字段 | 简道云字段 | 来源类型 | 衔接说明 |
|---------|---------|:------:|---------|
| 品牌商城（聚合） | 品牌商城（关联数据） | 后端拼接 | 按 brand_id 拼接 ID |
