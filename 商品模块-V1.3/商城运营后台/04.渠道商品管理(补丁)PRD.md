## 1. 文档概述

### 1.1 项目背景
当前渠道商品管理页面仅支持查看已上架至各品牌商城的商品，操作较为单一（查看详情/改价）。随着多商城并行运营，运营人员需要：

1. **双视角管理**：既能从商品维度横向对比同一商品在不同渠道的售价差异，也能从渠道维度纵览某个商城下的全部在售商品。
2. **批量导入选品**：线下选品完成后，需要将选品清单快速导入渠道并自动执行异常校验。
3. **灵活的可售控制**：商品在渠道的可售/不可售状态需要行内快速切换，实现短暂的C端隐藏（不可售），与直接移出品牌商城列表区别开。

### 1.2 项目目标
将渠道商品管理升级为渠道运营的核心工作台，实现：
1. **维度模式**：商品维度 + 渠道维度的自由切换，满足不同运营场景。
2. **批量导入选品**：上传 Excel → 系统执行前置异常校验（重复数据/利润预警/供应商优化/渠道冲突，详见《待处理选品(补丁)PRD》）→ 弹窗展示校验结果 → 正常商品进入定价推品配置页，异常商品转入待处理选品中心。
3. **可售状态管理**：每行商品支持一键切换可售/不可售，不可售商品在C端隐藏但后台保留数据。
4. **操作升级**：操作列调整为「查看→改价→移出」

### 1.3 与上下游模块的关系

| 关联模块 | 关系说明 |
|----------|----------|
| **选品清单管理** | 选品清单中发起"定价推品"后，正常商品经定价推品配置页最终上架至渠道，成为渠道商品管理的在售数据 |
| **待处理选品中心** | 渠道商品管理的"批量导入选品"经前置异常校验后，异常商品自动转入待处理选品中心（来源类型标记为"渠道导入"）；待处理中心处理完成的商品经定价推品配置页回流至渠道商品管理 |
| **供应链商品池** | 当供应链那边商品下架后，商城运营平台的供应链商品池下架后同步从渠道商品列表下架，但是在进行确认通知（作为异常商品自动转入待处理选品中心（来源类型标记为"存量巡检"） |

### 1.4 核心术语
- **渠道商品**：已通过定价推品流程、正式上架至某个品牌商城的商品。
- **商品维度**：以商品（SPU）为主键，同一商品在不同商城的渠道实例汇聚展示。
- **渠道维度**：以品牌商城为主键，展示该商城下所有在售商品。
- **可售/不可售**：商品在渠道的展示控制开关。可售=正常展示下单，不可售=C端隐藏但后台数据保留。
- **批量导入选品**：上传 Excel 将选品清单导入渠道管理 → 执行与定价推品一致的前置异常校验 → 正常商品流转至定价推品配置页。
- **移出**：将商品从目标商城永久移除，不可逆。与"不可售"（可恢复的C端隐藏）为两个独立操作。

## 2. 功能架构与交互总览

### 2.1 导航架构
- "渠道商品管理"作为二级菜单存在于系统左侧导航栏"选品管理"分组下，与"供应链商品池"、"选品清单管理"、"待处理选品"平级。
- 菜单可见性由 RBAC 权限点"模块可见"控制（详见 2.5）。

### 2.2 整体布局
页面为单页结构，自上而下：
- **顶部信息栏**：面包屑导航 + 当前用户信息 + 页面操作按钮（导入筛选、批量导入）。
- **统计区**：覆盖线上品牌商城数、渠道商品总数、可售商品数、不可售商品数。
- **展示模式切换**：商品维度 / 渠道维度选项卡。
- **筛选区**：包含高级筛选标签（导入筛选激活时显示）、商品名称搜索、品牌商城（多选）、供应商、销售模式、可售状态。
- **商品列表**：表格展示，商品维度支持分组展开/折叠。
- **底部批量操作栏（页面悬浮固定）**：批量导出、批量改价、批量加标签、批量去标签、批量可售、批量不可售、批量移出 + 分页。

### 2.3 模块概览
系统包含五大核心能力：
1. **双维度展示**：商品维度（默认）+ 渠道维度。
2. **批量导入选品**：上传 → 前置异常校验 → 结果弹窗 → 确认流转。
3. **可售状态切换**：行内一键切换按钮，即时生效。
4. **单行操作**：查看（进入商品详情页）、改价（触发改价申请）、移出（二次确认）。
5. **批量操作**：批量导出、批量改价、批量加/去标签、批量可售/不可售、批量移出。

### 2.4 数据来源与商品生命周期

渠道商品管理中的商品数据来源于以下路径：

```
供应链商品池 → 选品清单（勾选推品）→ 前置异常校验 ──正常──→ 定价推品配置页 ──→ 渠道商品管理（可售）
                                              │                                    │
                                              └──异常──→ 待处理选品中心 ──处理后──→ 定价推品配置页 ──→ 渠道商品管理
                                              
供应链商品池 → Excel批量导入 ──→ 前置异常校验 ──正常──→ 定价推品配置页 ──→ 渠道商品管理（可售）
                                              │
                                              └──异常──→ 待处理选品中心
```

**商品在渠道商品管理中的状态流转**：

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| 可售 | C端正常展示，可下单 | 定价推品上架成功 |
| 不可售（手动） | C端隐藏，后台数据保留 | 运营人员手动切换可售开关 |
| 不可售（供应链） | C端隐藏，后台数据保留 | 供应商涨价/下架经供应链审批后，系统自动将商品调整为不可售状态（见《待处理选品(补丁)PRD》3.5/3.6） |
| 已移出 | 从渠道永久移除 | 运营人员执行移出操作 |

> **不可售（手动）与不可售（供应链）的区别**：手动不可售可由运营人员随时切回可售；供应链触发的不可售需在待处理选品中心点击【确认并更新】后，商品恢复可售状态。两种不可售在列表中均显示为红色"不可售"标签，hover 展示具体原因。

| 批次 | 优先级 | 功能 | 理由 |

## 3. 核心功能说明

### 通用规则

#### 并发处理保护
- **可售状态切换**：以最后一次操作为准，不做并发锁（开关类操作，冲突概率低且后果可接受）。

#### 与待处理选品中心的联动规则
- 当商品在待处理选品中心因"成本变动"或"断供提醒"被调整为不可售状态后，渠道商品管理中该商品的**可售状态自动变更为"不可售"**，toggle 按钮旁显示红色小圆点标记表示"系统触发"，hover 提示具体触发原因（如"供应商已调价，请在待处理选品中心处理"）。运营人员不可手动切回可售，需在待处理选品中心点击【确认并更新】后由系统自动恢复可售状态。
- 当商品在待处理选品中心完成"移出渠道"操作后，该商品从渠道商品管理列表中**自动移除**。

### 3.1 双维度展示模式

页面顶部提供「商品维度」「渠道维度」两个选项卡，默认展示"商品维度"。

**模式一：商品维度（聚合视图）**

核心逻辑：以"商品（SPU）"为主键，将同一商品SKU在不同渠道的铺设情况进行折叠聚合。

适用场景：适合运营人员查看单品的全网分销情况（例如：查看某款iPhone在哪些商城上架了，价格是否统一）。

展示形式：
- **分组行（商品层）**：展示商品图片、名称、SPU编码，以及核心指标"覆盖商城数量"（如：已覆盖 3 个商城）。
- **子行（渠道层）**：点击分组行展开后，展示该商品在各个商城的具体表现，包括渠道价、可售状态及单渠道操作按钮。

排序规则：默认按商品首次添加时间倒序排列。

**模式二：渠道维度（卡片+详情页）**

核心逻辑：以"品牌商城（渠道）"为主键，采用"卡片概览 → 详情页精管"的两级页面结构。

适用场景：适合运营人员按渠道进行盘点和精细化运营（例如：专门负责"南航积分商城"的运营，需要对该渠道下的所有商品进行价格巡检和库存同步）。

一级页面 — 渠道管理首页（卡片视图）：
- 展示形式：网格状排列的渠道卡片。
- 卡片内容：渠道Logo、名称、对接状态；在售商品数、最近一次推品时间。
- 快捷操作：【管理商品】（进入详情页）。

二级页面 — 渠道详情页（单渠道商品列表）：
- 展示形式：平铺的商品明细表格。
- 列表内容：展示该渠道下的所有商品，包含商品信息、供货价、渠道价、毛利率、库存状态及销售状态开关。
- 全局操作：支持对该渠道商品进行批量下架、批量改价等操作。

**维度切换行为**
- 跨页勾选状态在维度切换后清除，切换时 Toast 提示"已切换视图，勾选状态已清空"。

### 3.4 可售状态切换

每行商品的可售状态以切换按钮控件展示，点击后在可售/不可售之间即时切换。默认状态为可售。

**视觉规范**
- **可售**：灰色背景开关（启用态）。
- **不可售（手动）**：红色背景开关（关闭态），无额外标记。
- **不可售（供应链）**：红色背景开关（关闭态），按钮旁显示红色小圆点标记，hover 提示"供应商已调价/下架，请在待处理选品中心处理"，开关本身置灰不可点击。

**交互规则**
- 手动切换需二次确认，弹窗提示"确认将该商品设为不可售？C端将隐藏该商品"，确认后即时生效并 Toast 提示变更结果（如"已将该商品设为不可售"）。从不可售切回可售无需二次确认。
- 供应链触发的不可售状态不可手动切回，运营人员需前往待处理选品中心完成对应处理后方可恢复。
- 不可售商品在C端小程序/商城前端即时隐藏，后台数据完整保留（包括价格、库存、订单关联）。

> **设计决策**：设为不可售需二次确认（防止误操作导致C端意外隐藏），切回可售无需确认（恢复性操作，误触成本低）。移出操作为不可逆，单独走二次确认（见 3.5）。

### 3.5 单行操作

| 操作 | 触发行为 | 权限 |
|------|----------|:----:|
| **查看** | 进入商品详情页（新开Tab），展示商品完整信息、渠道分布、历史操作记录 | viewer+ |
| **改价** | 触发改价申请流程（此处暂不展开，与改价申请模块联动） | operator+ |
| **移出** | 弹出二次确认弹窗，展示待移出商品明细（商品名/SKU/目标商城）+ 警告文案"移出操作不可逆，若需重新上架需从选品清单重新走定价推品流程"→ 确认后从该商城永久移除 | manager+ |

**移出操作的边界处理**：
- 商品存在进行中/待处理订单或售后时，可正常执行移出。现有订单/售后继续履约至完成，移出后该商品不再产生新订单。
- 商品在多个商城上架时，移出操作仅影响当前目标商城，不影响其他商城的在售状态。
- 移出后该商品行从列表中消失（若为商品维度分组行下的唯一子行，分组行同步移除），已关闭的商品暂时不移入任何归档列表。

### 3.6 批量操作

底部批量操作栏悬浮固定，实时显示已勾选商品数量（如"已选 12 项"）。未勾选任何商品时批量操作按钮置灰。

**复选框交互**
- 列表顶部提供全选复选框，点击后选中当前页全部可勾选记录，再次点击取消全选。
- 支持跨页勾选：勾选后翻页不清除已选记录，系统维护一份完整的"已勾选集合"。
- 点击批量操作时若未勾选任何商品，Toast 提示"请先勾选要操作的商品"。

**批量改价**（此处暂不展开，与改价申请模块联动）

**批量加标签**（标签逻辑待定，按钮入口已预留）

**批量去标签**（标签逻辑待定，按钮入口已预留）

**批量可售**
- 勾选一条或多条商品后点击，弹出二次确认："确认将已选的 N 个商品批量设为可售？"
- 确认后，所有已勾选商品的可售状态批量切换为"可售"。
- **边界规则**：不可售（供应链）即 `locked` 状态的不参与批量切换，跳过数量在操作完成后 Toast 提示（如"已批量设为可售：12 项，跳过 2 项系统锁定商品"）。

**批量不可售**
- 勾选一条或多条商品后点击，弹出二次确认："确认将已选的 N 个商品批量设为不可售？"
- 确认后，所有已勾选商品的可售状态批量切换为"不可售"。
- **边界规则**：同批量可售，locked 状态不参与切换。

**批量移出**
- 勾选多条商品后点击，弹出二次确认弹窗。
- 弹窗展示全部待移出商品明细表格，含商品名称/SKU/目标商城，支持展开/折叠查看。
- 明细表格默认折叠，仅展示汇总数字与展开按钮（格式：`待移出商品明细 ▾ （共 N 条）`），展开后箭头旋转 90° 向上 `▴`，完整展示所有明细行。
- 警告文案："批量移出操作不可逆，确认后将所选商品从对应渠道永久移除。"
- 确认后执行批量移出，已勾选的不可售（供应链）商品自动跳过并在完成后提示跳过数量。
- 单次批量移出上限 200 条，超过时提示"单次最多移出200条商品"。

**批量导出**
- 勾选一条或多条记录后点击，导出已勾选记录的核心字段为 Excel 文件（.xlsx）。
- 后台异步生成，完成后通过站内消息/通知中心推送下载链接。
- 导出为纯数据输出操作，不改变任何商品状态。

### 3.7 批量导入选品

**入口**：页面右上角【批量导入选品】按钮。

点击后触发三步流程：

**Step 1 — 文件上传**

弹出模态框，展示拖拽/点击上传区域：
- 提示文案："支持 .xlsx 格式，单次最多导入 500 条商品"。
- 底部提示："导入后系统将自动执行前置异常校验（重复数据/利润预警/供应商优化/渠道冲突）"。
- 文件格式校验：非 .xlsx 文件被拦截，Toast 提示"请上传 .xlsx 格式文件"。
- 空文件或仅含表头：提示"文件中未检测到商品数据，请检查文件内容"。

**Step 2 — 解析与校验（处理中）**

点击上传后展示处理中状态：旋转加载动画 + "正在解析文件并执行前置异常校验..." + 进度条动画。

校验逻辑与选品清单"定价推品"的前置异常校验完全一致（详见《待处理选品(补丁)PRD》3.0）：

> **注意**：成本变动与断供提醒属于存量巡检类异常，导入后商品正式上架，后续由系统日常巡检覆盖这两类异常。

**Step 3 — 校验结果弹窗**

校验完成后在同一模态框中展示结果：

- **汇总横幅**：黄色背景展示"共解析 N 条商品，其中 X 条存在异常，Y 条可正常进入定价"。
- **统计卡片**：三列（选品总数 / 正常商品 / 异常商品），正常为绿色数字，异常为红色数字。
- **异常商品明细表格**：展示异常类型标签、商品信息（名称+SKU）、异常原因。表格默认折叠，点击"异常商品明细 ▾（共 X 条）"展开查看。
- **全正常场景**：跳过异常明细表格，直接展示汇总横幅 + 统计卡片，底部按钮变为【全部商品进入定价（N条）】。
- **全异常场景**：正常商品数量为 0 时，【仅正常商品进入定价】按钮置灰并提示"无正常商品可进入定价"。
- **底部按钮**：
  - 【仅正常商品进入定价（Y条）】：主按钮，正常商品流转至定价推品配置页，异常商品自动转入【待处理选品中心】（来源类型标记为"渠道导入"），弹窗关闭，页面跳转至定价推品配置页。
  - 【返回上传】：回到 Step 1 重新选择文件。
  - 【取消】：关闭弹窗，不做任何导入。

**中断与异常处理**
- 导入过程中关闭浏览器/弹窗：未完成导入的商品不做任何持久化，下次打开时重新上传。
- 导入过程中网络中断：前端展示"网络异常，请重新上传"，已部分写入的数据由后端事务回滚。

### 3.8 导入筛选

运营人员经常需要从大量商品中快速定位几十个特定SKU。"导入筛选"提供两种快捷方式将目标数据导入为筛选条件，瞬间定位目标行。

**入口**：页面右上角 `[导入筛选]` 按钮，位于 `[批量导入]` 按钮左侧。点击后弹出下拉菜单，提供两种方式：

**方式一：导入文件筛选**

1. 点击"导入文件筛选" → 展开上传区（虚线边框拖拽区）
2. 支持 .xlsx / .xls / .csv 格式，文件第一列为 SKU 编码或 SPU 编码
3. 选择文件 → 前端解析文件第一列数据，自动去重去空 → 作为筛选关键词集合
4. 自动执行筛选：表格仅展示匹配行
5. 筛选栏出现蓝色标签 `导入筛选: N条`，点击 × 清除恢复全部

**方式二：批量粘贴筛选**

1. 点击"批量粘贴筛选" → 展开 textarea 面板
2. 粘贴 SKU/SPU 编码，支持换行、逗号、Tab 分隔
3. 实时识别关键词数量并去重显示（"已识别 N 条关键词"）
4. 点击 [应用筛选] 或 Ctrl+Enter → 表格仅展示匹配行
5. 筛选栏出现蓝色标签 `导入筛选: N条`，点击 × 清除

**高级筛选标签**

- 筛选激活后，筛选栏搜索框左侧出现蓝色标签：`[×] 导入筛选: N条`
- 样式：蓝色背景 + 蓝色边框，区别于普通筛选
- 点击 × → 清除导入筛选条件，恢复全部数据展示
- 切换商品维度/渠道维度 → 导入筛选保持激活
- 标签同时在商品维度筛选栏和渠道维度筛选栏显示

**边界规则**

| 场景 | 处理方式 |
|------|----------|
| 空文件/仅表头 | 提示"未识别到有效关键词，请检查文件内容" |
| 文件超过1000行 | 取前500行 |
| 粘贴内容为空 | 提示"请粘贴至少一条关键词" |
| 筛选结果为空 | 表格显示空状态，标签仍显示"导入筛选: N条 · 0条匹配" |
| Excel解析（无xlsx库） | 尝试按文本解析，提示"Excel解析需要xlsx库，已尝试按文本解析" |

## 4. 边界条件与异常处理

| 场景 | 处理方式 |
|------|----------|
| **筛选结果为空** | 表格区域展示空状态插画与文案："暂无符合条件的渠道商品，请调整筛选条件" |
| **商品在所有商城被移出** | 该商品行从列表中消失，统计区"渠道商品总数"自动更新 |
| **移出存在进行中订单/售后的商品** | 可正常移出，现有订单/售后继续履约至完成，移出后该商品不再产生新订单 |
| **同时多人操作同一商品** | 可售切换以最后一次为准；移出操作加行级锁，后到者看到置灰按钮 |
| **导入文件超过500条** | 前端校验文件行数，超过时提示"单次最多导入500条商品，请拆分文件后重新上传" |
| **导入文件格式错误** | 非 .xlsx 拦截并提示；.xlsx 但列映射失败时提示"文件列格式不匹配，请使用标准模板" |
| **切换维度时存在勾选** | 勾选状态清空，Toast 提示"已切换视图，勾选状态已清空" |
| **批量移出超过200条** | 提示"单次最多移出200条商品，请减少勾选数量" |
| **网络中断导致操作失败** | 展示明确的错误 Toast，数据回滚至操作前状态 |

## 5. 视觉与体验规范

- **空状态设计**：无数据时展示正向插画与文案："暂无渠道商品数据"，若筛选条件非空则提示"请调整筛选条件"。
- **列表默认排序**：商品维度按商品首次添加时间倒序排列；渠道维度（详情页）按最近上架时间倒序排列。
- **即时反馈机制**：可售状态切换即时生效并 Toast 提示；移出成功后该行立即从列表消失；批量导入完成后跳转至定价推品配置页。
- **视觉降噪**：列表行背景色保持清爽，仅在"可售状态"切换按钮和"来源类型"标签上使用区分色，避免整行高亮变色造成视觉疲劳。
- **表格展开/折叠动画**：分组行展开箭头动画 160ms ease，子行展开时带轻微过渡。
- **弹窗明细折叠规范**：所有涉及商品列表的弹窗（校验结果弹窗、移出确认弹窗等），商品明细表格默认折叠，仅展示汇总数字与展开按钮（`▾`）。展开后箭头旋转为 `▴`，表格完整展示。折叠后恢复 `▾`，表格隐藏，汇总数字保留可见。
