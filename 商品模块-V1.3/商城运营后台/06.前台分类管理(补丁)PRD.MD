## 1. 文档概述

### 1.1 项目背景
当前商城前台分类直接沿用供应链标准类目，无法满足运营侧针对大促、节日、渠道差异化等场景的灵活展示需求。同时，所有品牌商城渠道共享同一套分类结构，无法按渠道做差异化导航。此外，分类调整直接作用于线上，缺乏草稿/发布隔离机制，运营在调整过程中可能影响消费者体验。

本迭代在供应链标准系统类目之上，建立"基础分类映射完善 + 营销分类独立建设"的分层体系：系统类目由供应链自动同步作为数据底座，运营可在此基础上映射编辑基础分类（调整名称/图标/排序/渠道等前台展示属性），同时可独立新建营销分类应对主题活动场景，并通过草稿/发布机制安全推送至品牌商城。

### 1.2 项目目标
建立"系统类目（数据底座）+ 基础分类（映射完善）+ 营销分类（独立建设）"分层体系，实现以下目标：
1. **分层分类体系**：供应链系统类目自动同步作为数据底座；运营在此基础上映射编辑基础分类（调整名称、图标、排序、渠道等前台属性），并可创建虚拟分类补充导航结构；同时独立新建营销分类应对大促/节日等主题活动，三者混合编排展示。
2. **多渠道差异化展示**：为分类指定适用渠道，实现不同端展示不同的分类结构。
3. **安全发布机制**：引入草稿/发布版本隔离，运营编辑不影响线上，确认后一键发布推送至品牌商城后台。
4. **前端精准渲染**：各端根据渠道标识拉取对应分类数据，确保所见即所得。

### 1.3 核心术语与分类体系

本模块的分类体系分为三层：

```
系统类目（数据底座） ──供应链同步──→ 系统类目Tab只读展示
        │
        ├── 映射编辑 ──→ 基础分类（前台导航主体）
        │                   ├── 系统类目节点（映射系统类目，多选）
        │                   └── 虚拟分类（关联选品清单，单选）
        │
        └── 独立于类目树 ──→ 营销分类（主题活动）
```

**三层分类定义**

| 层级 | 名称 | 来源 | 管理Tab | 说明 |
|------|------|------|:------:|------|
| 数据底座 | **系统类目** | 供应链自动同步 | 系统类目 | 三级树形，只读，不可增删 |
| 前台导航 | **基础分类** | 映射编辑 + 手动创建 | 基础分类 | 三级树形，C端导航主体 |
| 主题活动 | **营销分类** | 运营手动创建 | 营销分类 | 三级树形，独立于基础分类树 |

---

**① 系统类目**（数据底座）

来源于供应链标准类目的分类节点，是商品的固有属性。每个商品有且仅有一个系统类目，由供应链数据决定。类目结构（层级/是否存在）以供应链为准不可增删。系统类目自动同步至「系统类目」Tab中以三级树形只读展示，不作为前台导航直接使用。

---

**② 基础分类**（前台导航主体）

C端分类页的树形导航结构，在「基础分类」Tab中统一管理。每个节点分为两种节点类型：

| 节点类型 | 可否包含子级 | 可否关联商品 | 说明 |
|:------:|:--:|:--:|------|
| **目录** | 是 | 否 | 纯导航分组，不可关联商品 |
| **节点** | 否 | 是 | 末级叶子，直接关联商品SKU |

基础分类内的节点按来源分为两种：

| 来源 | 名称 | 创建方式 | 关联商品方式 | 可否删除 |
|------|------|------|------|:--:|
| 供应链映射 | **系统类目节点** | 供应链同步后运营编辑前台属性 | **映射系统类目（多选）** | 否 |
| 运营创建 | **虚拟分类** | 运营手动创建 | **关联选品清单（单选 + 同步）** | 是（需过引用校验） |

- **系统类目节点**：供应链类目同步后，运营可编辑其**名称、图标、排序、启用状态、C端分类页展示状态、适用渠道**等前台属性（名称默认与供应链一致，修改后不随供应链更新覆盖）。类型标签 `基础-系统`（蓝）。系统类目节点可直接映射系统任意层级类目（含三级），亦可通过【同步映射系统类目】按钮批量建立映射，三级类目映射后作为基础三级节点承载商品。
- **虚拟分类**：运营手动创建，可挂载为一级节点（与系统类目同级）或挂载在系统类目下作为子节点。关联商品仅支持**关联选品清单（单选）**，点击【同步】将清单内商品纳入。类型标签 `基础-目录`（蓝）或 `基础-虚拟`（绿）。

---

**③ 营销分类**（独立主题活动）

完全由运营自定义，独立于基础分类树，用于大促、节日、频道等场景。在「营销分类」Tab中管理。支持三级树形，节点类型同样分为**目录**（不可关联商品）和**节点**（直接关联商品）。商品关联方式为**关联基础分类（多选）+ 关联选品清单（单选+同步）**，两种可同时选择取并集。可跨系统类目选品。类型标签 `营销-目录`（橙）或 `营销-节点`（橙）。

---

**通用属性**

- **自定义分类**：虚拟分类与营销分类的统称，均由运营手动创建、可删除（需过引用校验）。品牌商城后台仅可新增营销分类。
- **适用渠道**：指定分类在哪些品牌商城展示。新建/编辑时支持**全部渠道**（默认）或**指定渠道**（多选）。系统类目默认全部渠道。
- **启用状态**：控制分类是否生效。停用后前端不可见、金刚区不可选，C端分类页展示状态强制隐藏。
- **C端分类页展示状态**：在启用前提下控制分类页导航是否显示。隐藏后分类页不可见但金刚区仍可跳转。
- **草稿态 / 发布态**：编辑保存后进入草稿态不影响线上；发布操作将草稿覆盖至发布态推送品牌商城。

**启用/展示双状态规则**：

| 启用状态 | C端分类页展示状态 | 分类页导航可见 | 金刚区可选 |
|:--------:|:--------:|:------------:|:--------:|
| 启用 | 显示 | 是 | 是 |
| 启用 | 隐藏 | 否 | 是 |
| 停用 | 隐藏（强制） | 否 | 否 |

- 停用时C端分类页展示状态强制为隐藏，不可单独设为显示。

### 1.4 商品与分类的归属模型

```
商品 ──必选── 1个 系统类目（供应链决定，商品固有属性）
商品 ──可选── 0~N个 虚拟分类（运营手动关联，可一级或挂载系统类目下）
商品 ──可选── 0~N个 营销分类（运营手动关联，独立于类目树）
```

**关键约束**：
- 系统类目是商品在供应链中的"家"，每个商品必属于一个系统类目。类目结构（层级/是否存在）由供应链决定，不可手动增删，但运营可修改类目的名称、图标等前台展示属性。
- 虚拟分类仅支持**关联选品清单（单选）**方式关联商品，选择后点击【同步】将清单内商品纳入该分类。挂载为一级节点时不限商品系统类目来源；挂载在系统类目下时须属父级系统类目。
- 营销分类是跨系统类目的"主题活动"，支持三级树形结构，不受系统类目树约束（如"中秋礼盒 > 传统糕点 > 月饼精选"可包含生鲜、酒水、糕点等多类目商品）。
- 商品在前台分类页中的展示位置：由系统类目和虚拟分类的一级节点共同构成导航，用户进入后看到对应商品；同时也可能出现在一个或多个营销分类叶子节点下。

## 2. 功能架构与交互总览

### 2.1 三端架构与数据流

本功能涉及三个端的协同工作：

```
┌─────────────────────────────────────────────────────────────────┐
│                     商城运营平台（商品中心）                        │
│                                                                 │
│  可操作：                                                        │
│  · 自动同步供应链类目（有商品则类目自动出现）                      │
│  · 创建虚拟分类（可作为一级节点或挂载在系统类目下），关联商品         │
│  · 创建营销分类（跨类目选品，最多三级）                             │
│  · 调整排序权重、C端分类页展示状态（显示/隐藏）                    │
│  · 为每个分类指定适用渠道（推送到哪些品牌商城）                      │
│  · 发布更新 → 将基线数据推送至品牌商城后台                          │
│                                                                 │
│  展示内容：                                                       │
│  · 分类树（系统类目 + 虚拟分类）的草稿态与发布态                    │
│  · 最近一次发布更新的时间                                           │
│  · 各分类的关联商品数、适用渠道                                    │
└──────────────────────┬──────────────────────────────────────────┘
                       │  发布推送（基线数据）
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                     品牌商城后台（各商城独立）                      │
│                                                                 │
│  可操作：                                                        │
│  · 查看商品中心推送的基线分类数据                                  │
│  · 在基线之上新增营销分类（独立主题，跨类目选品）                     │
│  · 编辑基线分类的名称、图标                                        │
│  · 隐藏基线的部分分类（不可删除基线数据）                           │
│  · 管理商城侧分类的C端分类页展示状态                               │
│  · 同步小程序                                                    │
│                                                                 │
│  展示内容：                                                       │
│  · 基线分类列表（来自商品中心，灰色标记来源）                       │
│  · 本商城新增的分类（与基线合并展示）                               │
│  · 最近一次同步小程序的时间                                         │
│  · 最终生效的分类结构预览                                         │
│                                                                 │
│  商城侧不做基础/营销双Tab，统一列表通过"分类类型"列区分：              │
│  · 基础分类（系统类目与虚拟分类合并，不区分来源）                    │
│  · 营销分类                                                       │
└──────────────────────┬──────────────────────────────────────────┘
                       │  最终分类数据
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                     小程序端（C端用户）                            │
│                                                                 │
│  展示内容：                                                       │
│  · 分类页：左侧一级类目 → 右侧子分类/虚拟分类入口/商品列表          │
│  · 营销分类入口（可以在金刚区图标或分类页顶部Tab）                   │
│  · 金刚区跳转到的分类详情页                                       │
│                                                                 │
│  交互行为：                                                       │
│  · 浏览分类、查看商品                                             │
│  · 断网时使用本地缓存兜底                                         │
│  · 记住上次浏览的分类位置                                         │
└─────────────────────────────────────────────────────────────────┘
```

**数据流向**：

| 流向 | 说明 |
|------|------|
| 供应链 → 商城运营平台 | 供应链标准类目同步，作为系统类目数据源 |
| 商城运营平台 → 品牌商城后台 | 运营发布后，分类基线数据推送至目标商城 |
| 品牌商城后台 → 小程序端 | 后台同步小程序后，商城侧最终分类结构（基线 + 自有新增 - 隐藏项）提供给前端 |
| 小程序端 → 品牌商城后台 | 携带渠道标识（品牌商城ID）请求分类数据 |

**各端职责边界**：

| 端 | 职责 | 不可做的事 |
|----|------|-----------|
| 商城运营平台 | 编排分类结构、关联商品、指定适用渠道、设置推荐排序、发布推送 | 控制商城侧最终展示和最终排序（那是品牌商城后台的事） |
| 品牌商城后台 | 接收基线、新增营销分类、编辑基线分类名称/图标、隐藏分类、调整分类排序、控制本商城最终展示并同步小程序 | 删除基线分类、新增基础分类（系统类目/虚拟分类）、修改基线分类的商品关联 |
| 小程序端 | 渲染展示、用户交互 | 任何分类配置操作 |

### 2.2 商城运营平台 - 导航架构
- 在系统左侧导航栏设置【前台分类管理】二级菜单，与"渠道商品管理"、"选品清单管理"等核心模块平级。
- 菜单下含三个子Tab页签：【营销分类】、【基础分类】、【系统类目】。
- 菜单可见性由RBAC权限点控制（详见 2.4）。

### 2.3 商城运营平台 - 整体布局
- 左侧「前台分类树」（仅展示基础分类 + 营销分类的一级节点，不展示系统类目），顶部提供三种筛选切换——全部 / 仅启用 / 仅显示。右侧表格区根据Tab切换展示不同内容。
- **营销分类 Tab**（默认激活）：右侧展示营销分类列表（三级树形），顶部操作栏【新建营销分类】按钮。支持全部展开/收起。
- **基础分类 Tab**：右侧展示基础分类列表（三级树形），顶部操作栏【新建基础分类】和【同步映射系统类目】按钮。基础分类节点类型分为目录和节点（叶子），仅节点可关联商品。目录行支持【新建子分类】。筛选栏支持分类名称、启用状态、C端分类页展示状态、适用渠道筛选。支持全部展开/收起。
- **系统类目 Tab**：右侧展示供应链同步的三级类目树（只读）。列包含类目名称、类型（目录/节点）、关联供应链SKU数、关联渠道SKU数、更新人/时间。不可增删改，开关置灰。支持全部展开/收起。
- 【发布更新】按钮位于页面右上角（标题同行右侧），三个Tab共用，发布时系统类目属性变更、基础分类和营销分类的草稿合并推送。按钮下方显示「上次发布时间」。
- 各Tab各自独立维护右侧列表的筛选与展开状态。
- **左侧「前台分类树」交互**：左侧树展示基础分类和营销分类的一级节点（按排序混合），不展示系统类目。顶部固定「全部」节点（点击展示全部分类）。点击树节点可联动切换Tab并过滤表格。

### 2.4 商城运营平台 - RBAC权限配置

前台分类管理页面及各按钮权限遵循系统统一RBAC模型，按角色分配。

**角色定义**
| 角色 | 标识 | 说明 |
|------|------|------|
| 超级管理员 | admin | 系统最高权限，可执行所有操作 |
| 选品主管 | manager | 具备分类发布等敏感操作权限 |
| 运营专员 | operator | 日常分类维护，受限执行高风险操作 |
| 只读用户 | viewer | 仅可查看分类结构，不可编辑 |

**页面访问权限（可见/不可见）**
| 权限项 | admin | manager | operator | viewer |
|--------|:-----:|:-------:|:--------:|:------:|
| 访问前台分类管理页面 | ✓ | ✓ | ✓ | ✓ |
| 查看基础分类Tab | ✓ | ✓ | ✓ | ✓ |
| 查看营销分类Tab | ✓ | ✓ | ✓ | ✓ |

**基础分类Tab — 按钮级权限**
| 按钮/操作 | admin | manager | operator | viewer | 备注 |
|-----------|:-----:|:-------:|:--------:|:------:|------|
| 新建基础分类 | ✓ | ✓ | ✓ | — | — |
| 同步映射系统类目 | ✓ | ✓ | ✓ | — | 批量建立系统类目→基础分类映射 |
| 新增/编辑子分类 | ✓ | ✓ | ✓ | — | — |
| 拖拽排序 | ✓ | ✓ | ✓ | — | — |
| 显示/隐藏开关 | ✓ | ✓ | ✓ | — | — |
| 删除虚拟分类 | ✓ | ✓ | — | — | 需校验引用关系 |
| 发布更新 | ✓ | ✓ | — | — | 影响线上数据 |

**营销分类Tab — 按钮级权限**
| 按钮/操作 | admin | manager | operator | viewer | 备注 |
|-----------|:-----:|:-------:|:--------:|:------:|------|
| 新建营销分类 | ✓ | ✓ | ✓ | — | — |
| 编辑营销分类 | ✓ | ✓ | ✓ | — | — |
| 选品配置（关联SKU） | ✓ | ✓ | ✓ | — | — |
| 拖拽排序 | ✓ | ✓ | ✓ | — | — |
| 删除营销分类 | ✓ | ✓ | — | — | 需校验引用关系 |
| 发布更新 | ✓ | ✓ | — | — | 影响线上数据 |

**无权限交互规范**
- 当前角色无权操作的按钮：渲染为置灰（disabled）状态，hover 提示"当前角色无此操作权限，请联系管理员"。
- 页面不隐藏按钮（保持布局稳定），仅改变可交互状态。

### 2.5 开发优先级

| 批次 | 优先级 | 功能项 | 理由 |
|------|:------:|--------|------|
| P0 | 1 | 基础分类管理（CRUD + 树形展示 + 排序） | 核心数据结构，所有下游依赖 |
| P0 | 2 | 草稿/发布隔离 + 立即发布 | 安全发布基础能力，避免运营误操作影响线上 |
| P0 | 3 | 分类接口（渠道过滤 + 发布态返回） | 前端渲染的输入，无此接口前端无法适配 |

## 3. 核心功能说明

### 3.1 基础分类管理

**功能描述**
管理前台导航树中运营自定义的分类节点。基础分类由运营手动创建，通过关联系统类目或选品清单来确定商品来源。基础分类支持三级树形结构，节点类型分为目录（可包含子分类）和节点（末级，可关联商品）。

**树结构模型**
- 基础分类节点分为两种类型：`目录`（纯导航分组）和 `节点`（末级叶子）。
- 支持三级树形结构：一级目录可包含二级目录或二级节点；二级目录可包含三级节点；三级节点为末级，不可再分组。
- 基础分类与营销分类在「前台分类树」中按排序权重混合排列。

**商品关联规则**
- 基础分类通过以下方式关联商品，**只能二选一**（互斥），在新建/编辑弹窗中通过单选按钮组切换：
  - **映射系统类目（多选）**：选择供应链系统类目树中的任意层级类目（可多选，存储为逗号分隔ID），选中类目下全部商品自动纳入并同步更新。关联后分类来源标记为「系统」。
  - **关联选品清单（单选 + 同步按钮）**：选择一个选品清单，需手动点击「同步」将清单最新商品列表同步至该分类。商品从清单移除时，同步也会从分类移除。关联后分类来源标记为「虚拟」。
- 来源由关联方式自动推导，无需手动选择。
- **编辑分类时节点类型锁定**：编辑已有分类时，节点类型（目录/节点）单选按钮置灰不可修改，防止误操作变更类型。新建分类时正常可选。

**页面布局**
- 采用树形结构列表展示，一级分类为根节点，点击展开子级。
- 顶部操作栏：【新建基础分类】、【同步映射系统类目】、【全部展开/收起】。

**列表字段**
| 列 | 说明 |
|----|------|
| 前台分类名称 | 树形缩进展示。系统类目默认与供应链类目名一致可修改；虚拟分类自行命名 |
| 映射系统类目 | 系统类目节点显示供应链类目名称（只读）；虚拟分类显示"—" |
| 图标 | 缩略图，可自定义上传 |
| 关联商品数 | 格式"在售数/总数"（如"95/128"），点击查看明细。"在售数"指关联商品中当前在渠道可售状态的SKU数，"总数"为关联的全部SKU数。 |
| 类型 | `基础-目录`（蓝）/ `基础-系统`（蓝）/ `基础-虚拟`（绿）；目录无来源区分，节点按来源区分系统/虚拟 |
| 排序 | 数字（越小越靠前），支持拖拽或行内编辑 |
| 启用状态 | 开关控件，停用时C端分类页展示状态强制隐藏、分类页不可见、金刚区不可选 |
| 适用渠道 | 全选显示"全部渠道"；单选显示渠道名；多选显示首渠道名 + "等N个渠道"，与供应链商品池风格一致 |
| C端分类页展示状态 | 开关控件，启用时可设为隐藏（分类页不可见，金刚区仍可选） |
| 更新人/时间 | 审计信息 |
| 操作 | 系统类目：【编辑】；虚拟分类：【编辑】【关联商品】【删除】 |

---

**操作逻辑**

**(1) 供应链类目自动同步**

系统根据供应链商品池中的商品数据自动维护系统类目树。供应链类目下有在售商品时，该类目自动出现在前台分类树中；类目下所有商品下架/删除后，该类目自动从前台分类树中消失。同步通过供应链商品上下架事件实时触发，不需要运营手动操作。

- **新增类目默认值**：供应链类目首次同步出现时，适用渠道默认**全选**，启用状态默认**启用**，C端分类页展示状态默认**显示**，排序权重默认**999**（排在最后，运营手动调整）。运营后续可按需修改。
- **级联影响**：系统类目消失时，其下所有虚拟分类同步隐藏（不删除，待类目恢复后自动恢复显示）。若该类目或其下虚拟分类被营销分类引用为商品来源，营销分类中来自该来源的商品自动不再展示（来源关联保留，商品数为0）。
- **草稿态保护**：若运营已在草稿态中修改了某系统类目的名称/图标等属性，该类目消失（无商品）时草稿修改也随之隐藏；类目恢复后草稿修改自动恢复，不需重新编辑。

**(2) 同步映射系统类目**

点击操作栏【同步映射系统类目】按钮，系统自动扫描尚未映射到基础分类的供应链系统类目，批量建立映射关系。该操作为**一次性批处理**，仅建立缺失的映射，不修改已存在的映射关系。

- **扫描范围**：扫描**系统一级类目**（目录型，映射为基础一级目录）、**系统二级类目**（目录型，映射为基础二级目录）和**系统三级类目**（节点型/末级，映射为基础三级节点）。已映射的保留不动、未映射的跳过不处理。
- **去重逻辑**：以基础分类节点的 `映射系统类目` 字段为唯一判断依据，已存在映射关系的系统类目不会被重复创建。不按名称匹配。
- **新建默认值**：同步创建的节点来源标记为「系统」，前台分类名称直接取系统类目名（运营后续可按需修改），排序权重默认 **999**，适用渠道默认**全选**，启用状态默认**启用**，C端分类页展示状态默认**隐藏**（运营需手动设为显示后C端才可见）。更新人记录为「系统同步」。
- **停用类目跳过**：系统类目中启用状态为停用的类目及其子级，同步时自动跳过。
- **操作反馈**：同步完成后展示Toast提示新增数量；若无待映射类目则提示"所有可用系统类目已完成映射"。
- **草稿态**：同步创建的新增节点保存至草稿态，需发布后才推送至品牌商城后台。

**(3) 新增/编辑分类**

- **编辑系统类目节点**：系统类目由供应链同步产生，**不支持手动新增和删除**（层级关系以供应链数据为准）。运营可编辑：前台分类名称（默认与供应链类目名一致）、图标、排序权重、启用状态、C端分类页展示状态、适用渠道。映射系统类目为只读字段。
  - **名称覆盖策略**：运营修改前台分类名称后，若供应链侧类目名称发生变更，**不自动覆盖**运营已修改的名称（以运营修后值为准）。若运营从未修改过名称（即为默认值），则供应链类目名称变更时自动同步更新。系统通过"名称是否为手动修改"标记来判断，该标记在运营首次修改名称时置为 true，运营手动恢复默认值时重置为 false。
- **新增一级虚拟分类**：点击【新建基础分类】按钮，选择分类类型（目录/节点）、填写前台分类名称、选择所属上级、上传图标、选择适用渠道后保存。目录型不关联商品仅做导航分组，节点型创建后通过操作列的【关联商品】入口配置商品来源。
- **在系统类目下新增子级虚拟分类**：点击系统类目行内【新增子分类】，选择分类类型（目录/节点）、填写前台分类名称、上传图标、选择适用渠道后保存。目录型可在其下继续建子级；节点型为末级，通过【关联商品】入口配置商品来源。
- 虚拟分类的映射系统类目：虚拟分类仅支持关联选品清单，此列显示"—"。
- **商品类目变更处理**：若供应链侧某商品的系统类目发生变更（如从"米面粮油"重分类至"进口食品"），系统自动检测该商品是否被原类目下的虚拟分类关联。若存在关联，自动解除该商品与原虚拟分类的关联，并在操作日志中记录（原因："商品系统类目变更"）。运营无需手动清理。
- **适用渠道独立性**：虚拟分类的适用渠道可与父级系统类目不同。例如父级系统类目适用 [A, B, C] 三个品牌商城，虚拟分类可仅适用 [A, B]。在商城 C 中，父级系统类目正常展示但其下不出现该虚拟分类。

**(4) 查看商品/选品**

- **系统类目**：点击关联商品数弹出汇总弹窗，展示"在售数 N / 总数 M"。因系统类目下可能有海量商品，弹窗内提供【在供应链商品池中查看】按钮，点击后跳转至供应链商品池页面，自动以当前系统类目为筛选条件。
- **虚拟分类**：点击关联商品数弹出汇总弹窗，展示"在售数 N / 总数 M"。弹窗内展示最近添加的商品列表（分页），支持移除单个商品或追加选品。同时提供【在供应链商品池中查看】按钮，跳转至供应链商品池并以当前虚拟分类的SKU为筛选条件。

**(5) 排序**

支持行内拖拽排序或输入数字权重（越小越靠前）。商品中心设置的排序为**推荐排序**，发布后推送至品牌商城后台作为初始值，品牌商城后台可覆盖调整，最终排序以品牌商城后台为准。

- **一级节点**（系统类目 + 一级虚拟分类 + 一级营销分类）：三者共用同一排序权重空间，在C端左侧导航中混合排列。数字相同按最近更新时间排序。
- **子级节点**：虚拟分类排序权重仅在同父级系统类目下生效（兄弟节点间比较）；子级营销分类排序权重仅在同父级营销分类下生效。不同父级下的子节点排序互不影响。
- 排序变更保存至草稿态，发布后推送至品牌商城后台。

**(6) 启用/停用**

提供开关控件。停用后该分类在前端完全不可用（分类页不可见、金刚区不可选），C端分类页展示状态强制变为隐藏。启用后C端分类页展示状态恢复为停用前的值。

**父子联动规则**：父级系统类目停用时，其下所有虚拟分类自动不可访问（即使虚拟分类自身为启用状态），C端分类页不展示该分支；父级恢复启用后，子级虚拟分类按自身启用状态决定是否可见。

**(7) 显示/隐藏**

在启用状态下，控制该分类是否在分类页导航中显示。隐藏的分类在分类页不可见，但金刚区仍可配置跳转。停用时此开关置灰不可操作。

**父子联动规则**：父级设为隐藏时，其下虚拟分类在分类页中也不可见（即使自身为显示），金刚区若直链到子级虚拟分类仍可访问。

**(8) 关联商品弹窗**

- **查看态**（操作列【关联商品】按钮）：弹窗为只读。基础分类根据来源二选一展示——系统来源显示关联系统类目标签（可能多个）；虚拟来源显示关联选品清单下拉+【同步商品】按钮。
- **编辑态**（编辑弹窗中内置）：新建/编辑分类弹窗中内置关联商品配置区域（位于适用渠道下方）。基础分类中系统类目节点和虚拟分类采用不同关联方式（互斥不可切换），营销分类两个区域同时可见（关联基础分类 + 关联选品清单，可同时选择）。已关联的来源在查看态中展示，绑定类目的只读，选品清单可点击同步更新。

**(9) 状态变更下游影响汇总**

| 操作 | 商品中心列表 | 品牌商城后台 | 小程序分类页导航 | 小程序金刚区 | 子分类 |
|------|:--:|------|:--:|:--:|------|
| **启用 → 停用** | 开关关闭，C端分类页展示状态强制隐藏 | 商城侧列表中**不可见**（等同删除），商城侧在该分类下新增的子级虚拟分类同步隐藏，操作记录保留 | 不展示该分类及其子分类 | 配置时不可选，已配置的入口点击提示"该活动已下线" | 全部不可访问（即使子级自身启用），C端不展示该分支 |
| **停用 → 启用** | 开关打开，C端分类页展示状态恢复为停用前值 | 商城侧列表**恢复可见**，此前新增的子级虚拟分类同步恢复，隐藏/排序调整保留 | 按自身及父级C端分类页展示状态决定是否可见 | 恢复可选（需重新配置时可见） | 子级按自身启用状态恢复（停用前为启用的自动恢复） |
| **显示 → 隐藏** | 展示开关关闭 | 基线数据同步，商城可覆盖 | 分类页导航不展示 | **不受影响**，已配置入口正常跳转 | 子级在分类页中同步不展示；金刚区直链到子级仍可访问 |
| **隐藏 → 显示** | 展示开关打开 | 基线数据同步，商城可覆盖 | 分类页导航恢复展示 | 不受影响 | 子级同步恢复（自身为显示的前提下） |
| **发布推送** | 草稿覆盖至发布态 | 收到新版本基线，商城侧新增/隐藏/排序调整**保留**，新基线分类默认可见 | 按商城最终排序和C端分类页展示状态渲染 | 按商城最终数据更新候选列表 | — |
| **适用渠道缩减** | 渠道Tag更新 | 被移除的商城，该分类从导航中移除；商城侧此前对该分类的隐藏/新增子级操作记录保留 | 被移除商城不展示 | 被移除商城不可选 | 子级同步移除 |

**关键原则**：
- 停用与隐藏的核心区别：停用是"分类不存在了"（金刚区也不可用），隐藏是"导航里不显示但可以通过金刚区直达"。
- 品牌商城后台不可删除基线分类，但可自行隐藏。商品中心再次发布时，商城侧隐藏状态保留。
- 父子联动：父级停用/隐藏 → 子级在分类页不可见。但金刚区直链到子级时，隐藏场景下仍可访问，停用场景下不可访问。

**(10) 删除**

系统类目不可删除（来源为供应链同步）；虚拟分类可删除。删除前执行以下校验（按顺序）：

- **营销分类引用校验**：检查该虚拟分类是否被营销分类的"关联基础分类/虚拟分类"引用。若被引用则弹窗提示"该虚拟分类被 N 个营销分类引用（如：618专区、夏日清凉专区），删除后对应营销分类将失去此商品来源，确认删除？"，运营确认后解除对应营销分类的该关联来源，继续执行删除。
- **金刚区引用校验**：检查是否被金刚区入口引用。若被引用则弹出二次确认弹窗："该分类被 N 个金刚区入口引用，删除后对应金刚区入口将无法跳转到此分类。小程序端已内置兜底机制（用户点击时提示'该活动已下线'），确认删除？"。运营确认后执行删除，对应金刚区入口的跳转目标自动置为失效状态。
- 以上校验均通过后，执行删除，同时自动解除该虚拟分类下所有商品的关联关系。

### 3.2 系统类目管理

**功能描述**
系统类目由供应链商品池**自动同步**，运营不可手动增删改。系统类目为三级树形结构（一级 > 二级 > 三级），在独立的「系统类目」Tab中以只读表格展示。

**列表字段**
| 列 | 说明 |
|----|------|
| 系统类目名称 | 树形缩进展示三级层级 |
| 类型 | `目录`（灰）或 `节点`（灰），一级/二级为目录，三级为节点 |
| 关联供应链SKU数 | 供应链中该类目下全部SKU数量 |
| 关联渠道SKU数 | 各品牌商城中该类目下可售SKU数量（去重） |
| 更新人/时间 | 供应链侧最近更新人与更新时间，格式"更新人 + 更新时间"双行展示 |

**操作逻辑**
- 系统类目为只读，所有开关置灰，无增删改按钮。
- 支持树形展开/收起（全部展开/收起按钮对所有Tab生效）。
- 供应链类目下有在售商品 → 类目自动出现；无商品 → 类目自动隐藏。

### 3.3 营销分类管理

**功能描述**
完全由运营自定义的主题分类（如"618专区"、"夏日清凉专区"），用于大促、节日、频道等场景。营销分类支持三级树形结构（如"618专区 > 数码电器 > 3C电子设备"），与基础分类在同一个前端一级导航中混合展示，按排序权重交替排列。节点分为两种类型——**目录**（纯导航分组，不可关联商品）和**节点**（可关联商品）。

**页面布局**
- 树形结构列表展示，支持展开/收起子级、拖拽排序。
- 顶部操作栏：【新建营销分类】。

**列表字段**
| 列 | 说明 |
|----|------|
| 营销分类名称 | 树形缩进展示（支持三级），运营自行命名 |
| 节点类型 | `目录`（橙色标签，不可关联商品）/ `节点`（绿色标签，可关联商品） |
| 图标 | 缩略图，可自定义上传 |
| 关联商品数 | 格式"在售数/总数"，点击查看明细。目录固定显示"—"；节点显示实际数值 |
| 排序 | 数字（越小越靠前），一级节点与基础分类共用排序空间，支持拖拽或行内编辑 |
| 启用状态 | 开关控件，停用时C端分类页展示状态强制隐藏、分类页不可见、金刚区不可选 |
| 适用渠道 | 全选显示"全部渠道"；单选显示渠道名；多选显示首渠道名 + "等N个渠道" |
| C端分类页展示状态 | 开关控件，启用时可设为隐藏（分类页不可见，金刚区仍可选） |
| 更新人/时间 | 审计信息 |
| 操作 | 【编辑】/【删除】 |

**操作逻辑**

**(1) 多级结构**

营销分类支持三级树形结构，仅目录可嵌套，节点为末级：

- **目录**：纯导航分组节点。可包含下级目录或下级节点，但**不可关联商品**。目录在C端展示为分类导航入口，用户点击后进入下一级分类列表。目录的关联商品数固定显示"—"，选品配置入口置灰不可用。目录最多嵌套至二级（即一级目录 → 二级目录 → 三级节点）。
- **节点**：末级商品节点。**节点下不可再新增子级**，直接关联商品。C端点击节点直接进入商品列表。节点在新建后不可变更为目录。
- **类型变更**：目录在其下无任何子节点时，可降级为节点（变更后即可关联商品）。节点不可变更为目录。节点类型在编辑弹窗中修改。
- 一级营销分类（根节点）与基础分类在C端左侧导航中混合排列。一级节点可为目录或节点，运营按需选择。示例：`618活动（目录）→ 数码电器（目录）→ 3C电子设备（节点）`。

**(2) 选品配置**

仅**节点**可配置商品关联。目录的选品配置入口隐藏。营销分类**不限制二选一**，以下两种方式**可同时选择**（非互斥），在新建/编辑弹窗中两个区域同时可见，最终商品范围为各方式取并集：

- **关联基础分类（多选）**：选择一个或多个基础分类节点（复选框列表），该节点下全部商品自动纳入。
- **关联选品清单（单选 + 同步按钮）**：选择一个选品清单，需手动点击「同步」将清单最新商品列表同步至该分类。
- 营销分类**不限制商品必须属于同一系统类目**，可自由跨类目组合。已选商品以列表形式预览，关联基础分类的只读，选品清单关联的可同步更新。

**(3) 查看选品**

节点点击关联商品数，弹出汇总弹窗，展示"在售数 N / 总数 M"。弹窗内展示商品列表（分页），每行标注来源（关联类目/选品清单）。关联类目来源的只读，选品清单来源的可移除。同时提供【在供应链商品池中查看】按钮。目录关联商品数显示"—"，不可点击。

**(4) 渠道指定**

同基础分类的适用渠道逻辑，支持勾选该营销分类在哪些客户端展示。

**(5) 删除**

删除前执行以下校验：

- **金刚区引用校验**：检查当前节点及其所有子孙节点是否被金刚区入口引用。若任一节点被引用则汇总提示："该分类及子级中共 N 个节点被金刚区入口引用，删除后对应入口将无法跳转。小程序端已内置兜底机制（用户点击时提示'该活动已下线'），确认删除？"。运营确认后执行删除，所有受影响的金刚区入口跳转目标自动置为失效。
- **级联删除确认**：当前节点非叶子节点时，需二次确认"该分类下有 N 个子级分类，将一并删除，确认？"。
- 以上校验均确认后执行删除，同时自动解除所有受影响节点下的商品关联关系。

### 3.4 同步发布机制

**功能描述**
管理分类配置的版本发布。运营在商品中心完成分类编排后，通过发布操作将分类数据推送至品牌商城后台。品牌商城后台工作人员可在此基础上进行二次调整（新增营销分类 / 编辑基线分类名称图标 / 隐藏基线分类，不可删除基线、不可新增基础分类），最终由品牌商城后台控制前端实际展示的分类。

**两级管理模式**

```
商品中心（运营）                    品牌商城后台（商城工作人员）
     │                                      │
     ├─ 编排分类结构（基础+营销）           │
     ├─ 指定推送到哪些品牌商城              │
     ├─ 点击发布 ──→ 推送基线数据 ──→      ├─ 接收基线分类数据
     │                                      ├─ 在基线之上新增营销分类
     │                                      ├─ 编辑基线分类名称/图标
     │                                      ├─ 隐藏基线的部分分类
     │                                      └─ 控制前端实际展示
```

- **商品中心侧职责**：编排分类结构、关联商品、设置推荐排序，作为"推荐基线"推送至目标品牌商城。排序权重为推荐值，品牌商城后台可覆盖。
- **品牌商城侧职责**（详见 3.5 节）：接收基线数据后，根据本商城实际运营需求，在基线之上新增营销分类（独立主题）、编辑基线分类名称/图标，隐藏不适用的基线分类，调整分类最终排序。商品中心推送的基线分类不可被品牌商城删除（仅可隐藏），不可新增基础分类（系统类目/虚拟分类）。商城侧不做基础/营销双Tab，统一列表通过"分类类型"列区分基础分类与营销分类。

**入口位置**
【基础分类管理】与【营销分类管理】页面右上角，共用同一套发布逻辑（两个Tab的草稿合并发布）。

**核心逻辑**

- **草稿态保存**：所有增删改操作仅影响草稿数据，不改变线上。运营可随时修改草稿，不影响前端用户看到的分类。

- **发布确认弹窗**：点击【发布更新】后，弹出变更摘要弹窗。弹窗内按渠道维度分组展示本次变更预览（如"政企福利商城：新增分类 [N] 个、删除分类 [N] 个、排序变更 [N] 处、启用/停用变更 [N] 处、显示/隐藏变更 [N] 处、适用渠道变更 [N] 处"），供运营确认。

- **发布执行**：【立即发布】将草稿数据发布为线上版本。**仅发布启用状态的分类**，停用的分类不推送至品牌商城后台（品牌商城后台侧列表中不可见，详见 3.1）。发布时按每个分类的"适用渠道"字段自动过滤——仅将分类数据推送至其适用渠道对应的品牌商城后台。发布确认弹窗中展示按渠道维度的推送预览（如"政企福利商城：新增 N1 个分类，变更 M1 处"）。记录发布日志（操作人、时间、推送目标商城、各商城推送分类数）。品牌商城后台收到新版本后，此前商城侧做的增加/隐藏调整保留（新增的不受影响，隐藏的保持隐藏，新推送的分类默认可见）。

  - **适用渠道缩减处理**：若运营将某分类的适用渠道从 [A, B, C] 缩减为 [A, B]，发布后商城 C 的该分类自动从分类导航中移除。商城 C 此前对该分类的隐藏/新增子级等操作记录保留（不物理删除），若后续重新将商城 C 加入适用渠道并发布，此前的操作记录自动恢复生效。
  - **并发编辑提示**：两个 Tab（基础分类/营销分类）共用同一发布按钮。若多个运营同时在两个 Tab 编辑，各自保存后草稿合并，发布时统一推送。建议在发布确认弹窗中提示"以下变更来自基础分类和营销分类的合并草稿"，避免运营误以为只发布了自己编辑的内容。

### 3.5 品牌商城后台分类管理机制

**功能描述**
品牌商城后台接收商品中心推送的基线分类数据后，商城工作人员可在基线之上进行二次编排。商城侧操作**直接生效**（无草稿/发布隔离），因商城侧调整仅影响本商城，风险可控。

**新增分类规则**
- **仅可新增营销分类（目录/节点）**：最多3级，遵循目录/节点双节点模型——目录不可关联商品仅做导航，节点可关联本商城在售商品，支持跨系统类目选品。**不可新增基础分类（系统类目/虚拟分类）**。
- **分类类型筛选**：商城侧不做基础/营销双Tab，统一列表通过"分类类型"列区分——仅区分**基础分类**（系统类目与虚拟分类合并，不区分来源）和**营销分类**两种类型。并可通过"来源"列筛选（基线/自有）区分商品中心推送与商城自建。
- **引用规则**：商城侧新增的营销分类可引用基线基础分类（系统类目+虚拟分类）作为商品来源；不可跨品牌商城引用其他商城的自建分类。

**编辑基线分类**
- 商城可编辑基线分类的**名称**和**图标**，修改后直接生效，不影响商品中心的原始数据。
- 不可修改基线分类的：商品关联关系、分类类型（系统/虚拟/目录/节点）、所属上级、适用渠道。

**隐藏与恢复**
- 商城可隐藏任意基线分类（基础分类/营销分类），隐藏后C端不可见但后台数据保留。
- 商品中心再次发布时，商城侧隐藏状态保留（即已隐藏的分类在新版本中继续保持隐藏）。
- 商城可随时恢复已隐藏的分类为可见。

**分类树筛选**
- 品牌商城后台分类树提供两种切换：**全部** / **仅显示**。仅显示模式下仅展示C端分类页展示状态为"显示"的分类（隐藏的分类不出现），方便商城工作人员预览C端实际可见的分类结构。
- 商品中心侧分类树提供三种切换：全部 / 仅启用 / 仅显示。仅启用过滤掉停用分类；仅显示在启用基础上进一步过滤掉隐藏分类。

**不可做的事（汇总）**
- 不可删除基线分类（仅可隐藏）
- 不可新增基础分类（系统类目/虚拟分类），仅可新增营销分类
- 不可修改基线分类的商品关联关系
- 不可修改基线分类的分类类型、所属上级、适用渠道
- （可编辑基线分类的名称和图标）

### 3.6 金刚区入口引用校验

**功能描述**
当运营在后台装修配置中设置金刚区入口跳转至某个分类时，系统需校验该分类的状态。

**校验时机与规则**
- **配置时校验**：运营选择跳转目标分类时，下拉列表仅展示"已发布 + 启用 + 包含当前渠道"的分类。已停用/不适用当前渠道的分类不出现。注意：隐藏但启用的分类可以出现在金刚区候选列表中。
- **运行时兜底**：当前端用户点击金刚区入口时，校验目标分类当前是否可访问。以下任一情况视为不可访问，前端展示兜底 Toast "该活动已下线"：
  - 分类已被删除（运营在后台二次确认后删除，金刚区入口跳转目标已置为失效）
  - 分类已停用
  - 分类不适用当前渠道
  - 分类尚未发布（草稿态）

  兜底提示为小程序端通用逻辑，不依赖后台实时接口——若接口返回目标分类不存在或不可访问，前端统一展示"该活动已下线"。

## 4. 小程序端需求（C端用户）

### 4.1 分类页面

**数据加载**
- 应用启动及下拉刷新时获取最新分类数据，请求时携带当前渠道标识（品牌商城ID）。
- 断网时使用本地缓存兜底，缓存超期则提示用户联网刷新。

**页面渲染**
- **左侧导航**：混合展示一级基础分类与营销分类（按品牌商城后台最终排序排列）。基础分类和营销分类可交替出现，如"米面粮油 → 618专区 → 酒水饮料 → 夏日清凉专区"。当前选中项高亮。
- **右侧内容**：
  - 选中基础分类（系统类目/虚拟分类）时：优先展示该类目下的虚拟分类入口（如"五常米专区"），下方展示全量商品列表。
  - 选中营销分类**目录**节点时：展示其下级目录/节点列表（如点击"618活动"展示"3C电子设备""家居生活"等），不展示商品。
  - 选中营销分类**节点**节点时：直接展示该节点关联的跨类目商品列表（节点为末级，无下级导航）。
- 营销分类同时也可作为首页金刚区入口，点击后直接进入对应分类。

**交互逻辑**
- 记录用户最后浏览的分类位置（一级分类ID），再次进入时自动定位。
- 左侧一级分类列表支持滚动，若分类数量较多，当前选中分类自动滚动至可视区域。

### 4.2 首页金刚区跳转

- **配置渲染**：根据后台装修配置，渲染金刚区图标及文案。
- **跳转逻辑**：
  - 跳转类型为"分类页"时，携带目标分类ID跳转至分类详情页。
  - 若目标分类不可达（已停用/已删除/不适用渠道），前端展示兜底 Toast "该活动已下线"。

## 5. 数据对接需求

### 5.1 前端获取分类数据

前端（小程序/APP/H5）请求分类数据时需携带渠道标识（品牌商城ID），服务端按以下规则过滤后返回：

1. 仅返回已发布的数据（草稿态数据不可见）。
2. 过滤掉当前渠道不适用的分类。
3. 过滤掉启用状态为"停用"的分类（停用需人工操作，无自动到期）。
4. 过滤掉C端分类页展示状态为"隐藏"的分类（金刚区直链单独处理，不在此过滤）。
5. 已失效商品（断供/下架/缺货）不展示，前端无感知。

返回数据为分类导航树，基础分类和营销分类作为一级节点按排序权重混合排列。基础分类节点下挂虚拟分类子节点；营销分类中目录节点下挂子目录或节点，节点为末级直接关联商品列表，目录节点商品列表为空。

### 5.2 推送至品牌商城后台

发布操作将分类基线数据推送至所选品牌商城后台，**仅推送启用状态的分类**（停用分类不推送），推送内容包括分类结构、商品关联关系、推荐排序与C端分类页展示状态。品牌商城后台接收基线后可进行二次调整（新增营销分类 / 编辑名称图标 / 隐藏 / 调整排序），最终排序以品牌商城后台为准。调整完成后由品牌商城后台将合并后的分类数据同步至小程序端，小程序直接使用无需再做排序处理。商城运营平台不直接与小程序端交互。

### 5.3 金刚区跳转校验

前端用户点击金刚区入口跳转分类页时，需校验目标分类在当前渠道是否可访问（未被停用/删除/渠道不匹配），不可访问时返回原因供前端展示兜底提示。

## 6. 边界条件与异常处理

- **发布并发控制**：同一时刻仅允许一个发布任务执行，后来者提示"发布进行中，请稍后再试"。
- **分类删除保护**：虚拟分类删除前依次校验营销分类引用（确认后解除）和金刚区入口引用（二次确认后允许删除，金刚区入口置为失效）。营销分类删除前校验金刚区入口引用（二次确认后允许删除）。删除父级营销分类时级联校验所有子级的金刚区引用，汇总提示。
- **发布生效延迟**：发布后可能存在短暂延迟（预期30秒内生效）。
- **空状态设计**：
  - 基础分类Tab无数据时，展示提示"点击「新建基础分类」开始创建"。
  - 营销分类Tab无数据时，展示"暂无营销分类，点击新建"并提供【新建营销分类】快捷入口。
  - 前端分类页无数据时（如所选渠道无可用分类），展示兜底提示"暂无分类，敬请期待"。

## 7. 视觉与体验规范

- **树形列表交互**：基础分类树形结构采用缩进 + 展开/收起箭头示意层级关系，拖拽排序时目标位置高亮示意可放置区域。
- **即时反馈机制**：新增/编辑分类保存后，列表即时刷新显示最新数据（草稿态）。发布成功后顶部展示绿色Toast"发布成功，预计30秒内生效"。
- **发布更新按钮状态**：当草稿数据与发布态无差异时，【发布更新】按钮置灰并提示"当前无待发布的变更"；存在差异时按钮高亮，并可显示变更数量角标（如"3项待发布"）。
- **视觉降噪**：分类类型标签仅在类型列使用区分色——系统类目灰（#6b7280）、基础-目录蓝（#2563eb）、基础-系统蓝（#2563eb）、基础-虚拟绿（#16a34a）、营销-目录橙（#d97706）、营销-节点橙（#d97706）。标签格式：目录统一为"基础-目录"；节点按来源分为"基础-系统"（映射系统类目）和"基础-虚拟"（关联选品清单）。列表行背景色保持统一白色，避免整行高亮造成视觉疲劳。
- **适用渠道标签**：参考供应链商品池风格——全选时显示"全部渠道"；单选时直接显示渠道名；多选时显示首渠道名 + 下方小字"等N个渠道"。

## 8. 与上下游模块的衔接关系

| 关联模块 | 关系方向 | 关系说明 |
|----------|:------:|----------|
| 品牌商城管理 | 上游（外部依赖） | **本模块依赖但该模块 PRD 尚未纳入当前文档体系。** 分类配置中"适用渠道"的选项列表来源于品牌商城管理的品牌商城列表（含品牌商城ID、名称、销售模式类型），分类接口的channel参数取值即为品牌商城ID。渠道的销售模式（直销/分销）由品牌商城管理定义，分类模块不感知此差异，仅透传渠道ID |
| 品牌商城后台 | 下游 | 商品中心发布分类后，将基线数据推送至目标品牌商城后台；商城工作人员可在基线上新增营销分类（独立主题），编辑基线分类名称/图标，或隐藏部分基线分类、调整最终排序后同步小程序。商城侧不做基础/营销双Tab，统一列表通过"分类类型"列区分**基础分类**与**营销分类**（系统类目与虚拟分类在商城侧统一归为基础分类，不区分来源） |
| 供应链商品池 | 上游 | 基础分类的系统类目数据来源于供应链标准类目自动同步（有商品则类目出现） |
| 选品清单管理（02） | 下游 | 虚拟分类和营销分类关联商品时，可从选品清单导入商品。导入后系统按虚拟分类的父级系统类目或营销分类的跨类目特性过滤商品 |
| 金刚区/首页装修配置 | 下游（外部依赖） | **该模块 PRD 尚未纳入当前文档体系。** 金刚区入口选择跳转目标分类时，依赖本模块的分类数据；分类删除/隐藏时需通知装修配置模块校验引用。金刚区模块需实现本 PRD 3.6 节中定义的配置时校验与运行时兜底逻辑 |
| 小程序端 | 下游 | 各端调用分类接口时携带渠道标识（品牌商城ID），依赖本模块的渠道过滤逻辑返回对应数据 |
| 商品标签管理 | 下游 | 标签分类树复用了前台分类的树形结构模式，共用 目录/节点 双节点类型模型。标签创建时只能关联到节点类型分类 |
