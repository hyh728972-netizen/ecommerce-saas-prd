## 1. 文档概述

### 1.1 项目背景
当前选品业务面临多渠道（政企福利商城、航司积分小站、商城会员购等）并行推品的需求。原有的单一商品池模式无法满足精细化的渠道策略与多人协同作业。

### 1.2 项目目标
建立"N*选品清单"作为选品作业的核心容器，实现以下目标：
1. **上游输入**：从"供应链商品池"中筛选商品，点击加入选品，弹窗勾选加入哪些选品清单（可多选），勾选并点击确认后加入对应的"选品清单A"
2. **中游作业**：在"选品清单"中进行多人协作、批量勾选与数据维护。
3. **下游输出**：勾选商品发起【定价推品】→ 系统执行前置异常校验 → 弹出校验结果弹窗 → 正常商品进入定价向导，异常商品自动流入"待处理选品中心"。

### 1.3 核心术语
- **选品清单**：承载一组商品的独立容器，具备独立的权限与生命周期。
- **定价推品**：将清单内勾选商品经过前置校验、定价配置后，正式分发至目标渠道的过程。

## 2. 功能架构与交互总览

### 2.1 导航架构
- "选品清单管理"作为二级菜单存在于系统左侧导航栏，与"渠道商品管理"、"供应链商品池"、"待处理选品"等核心模块平级。
- 菜单可见性由RBAC权限点"模块可见"控制（详见 2.4）。

### 2.2 整体布局
- **清单列表页**：卡片式布局，展示用户有权限访问的清单概览，顶部提供全局操作按钮。
- **清单详情页**：上下结构，顶部信息栏 + 筛选区 + 商品列表 + 底部批量操作栏（悬浮固定）。

### 2.3 模块概览
系统包含四大核心模块：
1. **清单管理中心**：清单的创建、配置、归档与权限管理。
2. **清单详情页**：商品的增删改查与基础状态展示。
3. **定价推品**：前置异常校验 → 弹窗确认 → 进入定价推品配置页（完成渠道选择与定价策略设置） → 执行推品。
4. **清单合并**：多清单汇总与冲突解决。

### 2.4 页面RBAC权限配置

选品清单管理的权限采用两层体系：

**模块级权限（RBAC）**

系统RBAC控制两个独立权限点，当前分配如下（暂定）：

| 权限点 | admin | manager | operator | viewer |
|--------|:-----:|:-------:|:--------:|:------:|
| 模块可见（导航栏菜单） | ✓ | ✓ | ✓ | — |
| 创建清单 | — | ✓ | — | — |

拥有"创建清单"权限的用户创建清单后，自动成为该清单的"清单创建人"。仅具备"模块可见"的用户可被添加为协作成员，但无法自行创建清单。

**清单级权限（清单创建人内部配置）**

清单创建人在拥有该模块"模块可见"权限的用户范围内，为清单选择协作模式：
- **团队协作**：创建人从可见该模块的用户中选择成员，分配以下两种角色之一：
  - **可编辑**：拥有清单内实质性操作权限（移出商品、发起定价推品、添加商品等）。
  - **仅查看**：仅可浏览清单内容，支持将商品数据批量导出（Excel），适用于数据核对与汇报。

**成员选择交互规范 —— 穿梭框（Transfer Box）**

新建清单与成员管理均采用"带角色分配的穿梭框"模式，核心设计如下：

**布局结构（左右分栏）**

| 左侧：待选成员 | 操作区 | 右侧：已选成员 |
|---|---|---|
| 搜索框（按姓名/部门过滤）+ 全选 | → 添加选中 | 成员姓名 |
| 部门分组列表 + 复选框 | → 添加全部 | 角色下拉框（可单独调整） |
| 显示待选总人数 | | × 移除按钮 / 显示已选总人数 |

**角色配置区（底部）**

- 下拉框设置"新成员默认角色"：可编辑 / 仅查看
- 默认值为**仅查看**，每次打开弹窗重置为仅查看，不记录上次选择
- 从左侧移入右侧的成员自动继承当前全局默认角色
- 右侧列表中可对单个成员单独修改角色，覆盖全局默认值

**适用场景**

此穿梭框模式统一应用于：
1. **新建清单**弹窗中的"协作成员配置"区域
2. 清单详情页顶部【成员管理】按钮触发的弹窗

**约束**

- 仅"清单创建人"可打开成员管理弹窗
- 新建清单时，至少需保留创建人本人为协作成员
- 可选成员范围为拥有该模块"模块可见"权限的全部用户

## 3. 核心功能说明

### 3.1 清单管理中心（清单列表页）

**可见范围**
用户仅能看到自己创建的清单 + 被他人添加为协作成员（可编辑/仅查看）的清单。

**卡片展示**
- **卡片字段**：清单名称、创建人、商品总数、协作人数、状态（进行中/已归档）、最后操作时间。
- **卡片操作**：进入清单

**全局操作**
- 【新建清单】：触发新建配置弹窗（详见 3.2）。仅具备"创建清单"RBAC权限的用户可见。
- 【合并清单】：在清单列表页，勾选多个清单，点击【合并清单】（详见 3.5）
- 【批量归档】：勾选多个"进行中"清单后点击，弹出二次确认弹窗，确认后所选清单状态变更为"已归档"。已归档清单为只读状态，清单内商品不可再发起定价推品。支持从已归档恢复为进行中。
- 【批量删除】：仅"已归档"清单可删除。点击后弹出二次确认弹窗，确认后物理删除清单及其商品关联数据（商品本身不受影响）。

**清单状态说明**
新建清单默认为"进行中"。"已归档"仅支持人工手动变更（批量归档操作），系统不做自动归档。

### 3.2 新建选品清单

点击【新建清单】后，触发弹窗：

**基础信息**
- **清单名称**（必填）：限制50字以内，如"2024-Q2-航司积分选品"。

**创建类型**
- **从零开始**：创建空白清单，后续手动从商品池添加。
- **导入已有清单**：支持搜索并选择单个历史清单作为数据源，系统自动复制源清单内的商品数据到新清单中。导入规则：
  - 仅导入源清单中状态为"正常"的商品（已失效商品不导入）。
  - 渠道价与划线价跟随商品数据一并复制。

**权限配置**

采用穿梭框交互（详见 2.4 成员选择交互规范）：

- 左侧"待选成员"：展示拥有"模块可见"权限的全部用户，按部门分组，支持姓名/部门搜索。
- 右侧"已选成员"：显示已添加为协作成员的用户，每人可单独设置角色（默认"仅查看"）。
- 底部"新成员默认角色"：控制从左侧批量添加时的初始角色，每次打开默认为"仅查看"。
- 创建人本人默认自动纳入协作成员，不可移除。
- 不添加其他成员则等同于私有清单（仅创建人可访问）。

### 3.3 清单详情页（作业工作台）

**页面布局**
- **顶部信息栏**：显示清单名称、当前用户在该清单的权限身份（如"您是本清单创建人"）、协作头像组、【成员管理】按钮（仅清单创建人可见）。

**成员管理弹窗（穿梭框）**

点击【成员管理】按钮后，触发穿梭框弹窗，支持清单创建人调整协作成员及其角色：

- **左侧 · 待选成员**：展示拥有"模块可见"权限且尚未加入本清单的用户。支持搜索（姓名/部门）、部门分组展示、全选、复选框勾选。
- **右侧 · 已选成员**：展示当前清单的协作成员列表，每行显示成员姓名 + 角色下拉框（可编辑/仅查看）+ 移除按钮。
- **中间操作区**：
  - "添加选中"：将左侧勾选的成员移入右侧，角色继承底部默认设置。
  - "添加全部"：将左侧所有可见成员批量移入右侧。
- **底部角色配置**：下拉框设置"新成员默认角色"，默认值为"仅查看"，每次打开弹窗重置。
- **保存逻辑**：点击"保存变更"后，以右侧列表为准更新清单的协作成员；从右侧移除的成员即刻失去对该清单的访问权限。
- **头像联动**：保存后顶部信息栏的协作头像组即时刷新。
- **商品列表**：SPU-SKU 两级分组展开，支持分页加载（默认每页20条），列表默认按添加时间倒序排列。
- **底部批量操作栏**：【批量配价】【定价推品】按钮，显示已勾选商品数量。

**商品列表字段归属（SPU-SKU 两级结构）**

SPU 主行聚合，展开后显示 SKU 次行。勾选列、商品信息列、类目/品牌列合并为单列，采用高密度多行布局。

| 列 | SPU主行 | SKU次行 |
|----|---------|---------|
| ☐ 商品信息（合并列） | **4行高密度布局**（详见下方） | **3行布局**（详见下方） |
| 供应商 | 首供应商名 + "等N个供应商"（灰字） | 供应商名 + 优选/跟卖标签 |
| 商品标签(供应链) | 标签值（灰色） | — |
| 供货价 | 波动值（¥min-¥max） | 单价 |
| 电商参考 | 电商价（¥min-¥max） | 电商价（单价）+ 电商链接：点击跳转（蓝色） |
| 渠道价 | 波动值（¥min-¥max，默认空） | 数字输入框（可编辑权限下可修改） |
| 划线价 | 波动值（¥min-¥max，默认空） | 数字输入框（可编辑权限下可修改） |
| 库存 | 共享总库存 | — |
| 发货 / 物流 | — | 物流+时效 |
| 供货状态 | 聚合（全正常/部分失效/全部失效） | 正常供货 / 已失效 |
| 其他同款 | — | 有则橙色标签"N个同款"，无则"—" |
| 已上架渠道 | — | 渠道名 + "等N个渠道"（灰字） |
| 操作 | 查看 / 移出 | 查看 / 移出 |

**SPU 主行 "商品信息" 合并列 — 4行布局：**

```
☐ ▶ 🖼 品牌 商品名称                      ← 第1行：名称（加粗，13px；名称如已含品牌则不再重复前置）
   供应链SPU编码：ZD-A00001               ← 第2行：SPU编码（monospace 14px）
   品牌 | 类目路径                         ← 第3行：品牌与类目（灰色，分隔符浅色竖线）
   实物商品  2个SKU  1个跟卖               ← 第4行：商品类型标签 + SKU数量 + 跟卖数（橙色）
```

**SKU 次行 "商品信息" 合并列 — 3行布局：**

```
☐   🖼 品牌 商品名称 规格                  ← 第1行：名称+规格（如名称已含品牌则不再重复前置）
      规格：星野黑,12+256GB               ← 第2行：规格明细
      供应链SKU：HZ-B00003-001-DF-A001   ← 第3行：SKU编码（monospace 14px）
```

**供应商列新增：**

- **优选**：商品为优选时，供应商名下方显示绿色 `优选` 标签
- **跟卖**：SKU 供应商非 SPU 首个供应商时，供应商名下方显示橙色 `跟卖` 标签
- 两个标签样式统一：圆角 4px、padding 1px 6px，与实物/虚拟商品标签一致

**视觉规范：**

- 缩略图：SPU/SKU 统一 60×60px，SPU 蓝色 `#d4e0fc`，SKU 灰色 `#e8e6e2`
- 商品信息列字体统一 13px（monospace 14px 视觉补偿），行高 1.5
- 所有列 `vertical-align: top` 顶部对齐
- 标签圆角 `4px`（微圆角矩形），实物/虚拟标签 padding `1px 6px` 紧凑贴字
- 分页：每页 20 个 SPU

> 已失效的 SKU 行半透明展示，复选框置灰不可勾选，hover 提示"该商品已失效，无法推品"。

**供货状态**
位于商品列表"发货/物流"与"其他同款"列之间。商品在清单内仅保留两种供货状态：
- **正常供货**：商品在供应链中有效，库存充足，可直接参与后续的定价推品。
- **已失效**：商品在供应链中已下架、缺货或被供应商删除，无法进行推品操作。
- 补充逻辑实现**（目前供应链下架，商品已在渠道要在待处理选品进行进行提示，在选品清单要标记已失效，在供应链商品池直接移除）**

**操作逻辑**
- **表单操作列**：每行商品提供【移出】按钮（正常供货/已失效均可用），点击后将该商品从当前清单中移除（仅移除关联关系，商品本身在供应链商品池中不受影响），不可恢复。
- **去除全部失效**：当清单中出现”已失效”商品时，页面右上角出现【去除全部失效】批量快捷操作，点击后一键移除当前清单内所有”已失效”商品，弹出二次确认”将移除清单内全部已失效商品（N条），确认？”，确认后批量移除。
- **勾选与推品**：运营人员可勾选供货状态为”正常供货”的商品，点击底部批量操作栏的【定价推品】。
- 已失效商品不支持勾选（复选框置灰），hover提示”该商品已失效，无法推品”。
- **批量导入**：详情页右上角提供【批量导入】按钮，支持上传.xlsx文件将线下清单商品快速导入当前线上清单，实现统一管理。导入后系统自动执行SKU校验（详见下方"批量导入校验逻辑"）。
- **批量导出**：底部批量操作栏提供【批量导出】按钮，可勾选部分商品导出或默认导出全部商品为Excel文件，用于数据核对与汇报。

**批量导入校验逻辑**

用户通过【批量导入】上传.xlsx文件后，系统自动对导入商品逐条执行供应链SKU校验：

- **校验规则**：以"供应链商品池"中的SKU为基准，逐一匹配导入商品的SKU。
  - SKU在供应链商品池中存在 → 标记为**"正常供货"**，可正常参与后续定价推品。
  - SKU在供应链商品池中查不到 → 标记为**"已失效"**，商品已从供应链移除或从未录入。
- **导入结果弹窗**：校验完成后弹出结果汇总弹窗，展示：
  - 导入总数、正常供货数量、已失效数量。
  - 若存在已失效商品（N > 0），弹窗顶部突出警告提示：**"存在N条已失效商品，请及时寻找替代品"**。
  - 已失效商品列表（含商品名称、SKU、失效原因），支持展开/折叠查看明细。
- **用户决策**：
  - 点击【确认导入正常商品】→ 仅正常供货商品写入当前清单，已失效商品丢弃。
  - 点击【取消】→ 关闭弹窗，不做任何导入。
- **导入后行为**：已失效商品不进入清单；正常商品导入后按添加时间倒序展示在清单商品列表中。

**渠道价与划线价**

选品清单内每个 SKU 支持单独配置渠道价与划线价，作为定价推品时的预填数据带入配置页。

- **列位置**：在商品列表"电商价"与"库存"之间，新增"渠道价"和"划线价"两列。
- **SPU/SKU 层级**：
  - **SPU 主行**：展示该 SPU 下所有 SKU 的波动值（¥min-¥max），不可编辑。若下辖 SKU 均未填值，则显示"—"。
  - **SKU 次行**：可编辑的数字输入框，拥有清单"可编辑"角色的协作成员可点击单元格直接修改；"仅查看"角色只读展示。
- **默认值**：商品从供应链商品池加入清单时，两列均为空。
- **输入约束**：
  - 渠道价：仅校验非负数，无上限、无小数位限制。
  - 划线价：除校验非负数外，值必须 ≥ (渠道价 + 1)。若填入值小于该阈值，失焦时自动回退为渠道价 + 1，并 Tooltip 提示"划线价需大于渠道价至少1元"。若渠道价为空，则不触发此校验。
- **数据作用**：发起定价推品时，各 SKU 的渠道价与划线价作为预填值带入定价推品配置页，可被覆盖。

**批量配价**

清单详情页底部批量操作栏提供【批量配价】按钮，支持对勾选商品批量计算并写入渠道价与划线价。

- **触发条件**：勾选至少 1 个正常供货的 SKU 后，【批量配价】按钮可用。
- **弹窗内容**：点击后弹出"批量配价计算器"模态框，内容如下：

  | 公式 | 输入 |
  |------|------|
  | 渠道价 = 供货价 × | [数字输入框] 倍 |
  | 划线价 = 渠道价 × | [数字输入框] 倍 |

  - 两个倍率输入框均默认为空，需手动填入。
  - 仅校验倍率 ≥ 0，无上限限制，支持小数。
  - 保留2个小数位（如输入 1.05 倍）。

- **计算逻辑**（点击确认后执行）：
  1. 以每个勾选 SKU 的**供货价**（SKU 次行单价）为基准。
  2. 按公式依次计算：`渠道价 = 供货价 × 倍率₁`，`划线价 = 渠道价 × 倍率₂`。
  3. 若计算结果中划线价 < 渠道价 + 1，则自动修正为 `划线价 = 渠道价 + 1`（与单行编辑约束一致）。
  4. 计算结果直接覆盖写入该 SKU 的渠道价、划线价字段。
  4. 列表即时刷新，展示最新的渠道价与划线价。
  5. 若某倍率为 0 或空，则对应计算结果为 0（即允许设零）。
  6. 覆盖后无确认步骤，可直接在表格内手动微调。

- **空值与部分填充**：
  - 若仅填入渠道价倍率（划线价倍率为空），则仅计算并覆盖渠道价，划线价保持原值。
  - 若仅填入划线价倍率（渠道价倍率为空），则取 SKU 当前渠道价（若为空则视为 0）乘以倍率，覆盖划线价。

- **SPU 级勾选行为**：勾选 SPU 主行（级联勾选其下所有 SKU）时，批量配价对展开的所有 SKU 生效。

### 3.4 定价推品

当用户在清单内勾选商品并点击【定价推品】时，触发以下流程：

**3.4.1 前置异常校验（校验弹窗）**

点击【定价推品】后，系统实时对所选商品执行异常检测，弹出模态框"选品异常校验结果"展示检测结果（异常检测规则、弹窗内容结构、按钮交互详见《待处理选品(补丁)PRD》section 3.0"选品清单批量勾选进入定价的前置异常校验"）。

用户操作后分两种路径：
- 点击【仅正常商品进入定价】→ 正常商品进入 3.4.2（选择目标渠道），异常商品自动转入待处理选品中心。
- 点击【取消】→ 关闭弹窗，不做任何流转，返回清单详情页。

若所选商品全部正常（无任何异常），跳过弹窗，直接进入 3.4.2。

**3.4.2 定价推品配置页**（此处不展开）

### 3.5 清单合并

**触发场景**
多个运营人员分别完成了各自的子清单，需要汇总统一推品。

**操作入口**
在清单列表页，勾选多个清单（目前该操作只有清单创建人可以操作，属于创建清单的权限），点击【合并清单】。

**合并规则**
- 在列表页勾选 2 个以上清单后点击【合并清单】，弹窗列出所有已勾选的清单（全部默认参与合并）。
- 通过「基础清单」单选按钮指定以哪个清单为基础，其余清单的商品追加并入，生成一个新的汇总清单（源清单保持原样不删除）。
- **去重策略**：相同SKU的商品以基础清单的版本为准（其余清单重复SKU被基础清单覆盖），渠道价与划线价随SKU一并遵循此规则，覆盖详情在合并完成后以弹窗形式提示。
- **已失效商品**：不参与合并（自动跳过，合并完成后弹窗告知跳过数量）。
- **合并后清单权限**：合并后生成的汇总清单，创建人为执行合并操作的用户，默认设为"团队协作"模式。

**协作成员继承**

合并弹窗中，每个源清单行附带一个"继承协作成员"勾选项：

- 每个源清单显示当前协作成员人数预览（如"张选品、王专员、赵经理 共3人"）。
- 默认**不勾选**，合并后不继承该清单的协作成员。
- 勾选后方可继承；若源清单主复选框取消勾选（不参与合并），其"继承协作成员"选项自动置灰不可选。
- 多源勾选时，协作成员按姓名去重合并（相同成员只保留一份）。
- 若**全部不勾选**，合并后仅保留创建人本人为协作成员。
- 合并结果弹窗中补充一行："继承协作成员：N 人（来自 X 个源清单）"。

**合并结果**
生成一个汇总的总清单，用于最终的统一推品。

## 4. 边界条件与异常处理

- **仅模块可见但无任何清单权限**：进入模块后显示空白页，提示"暂无可用清单，请联系管理员添加您为协作成员"。
- **勾选全部为已失效商品**：【定价推品】按钮置灰（已失效商品不支持勾选，此场景为理论边界）。
- **清单内含"已失效"商品时**：【去除全部失效】按钮出现并可用。
- **并发编辑**：多人同时向同一清单添加商品时，以服务器接收顺序为准，后到的请求正常追加，不做冲突合并。移出商品操作为即时生效，若A正在浏览某商品详情而B已将其移出，A刷新后该商品消失。

## 5. 视觉与体验规范

- **空状态设计**：清单列表页无可用清单时，展示引导提示。清单详情页无商品时，展示插画与"暂无商品，请从供应链商品池中添加"，并提供【供应链商品池】快捷跳转。
- **列表默认排序**：清单列表页默认按最后操作时间倒序排列。清单详情页商品列表默认按添加时间倒序排列。
- **即时反馈机制**：移出商品后该行立即从列表消失；定价推品成功后 Toast 提示并跳转；异常商品转入待处理中心后的轻提醒详见《待处理选品(补丁)PRD》section 3.0"后续引导"。
- **视觉降噪**：已失效商品行以浅灰文字展示，与正常供货商品形成视觉区分。仅在"已失效"供货状态标签上使用灰色，避免整行高亮变色造成视觉疲劳。
