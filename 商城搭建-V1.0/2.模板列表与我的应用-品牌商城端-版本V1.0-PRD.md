# PRD：品牌商城端模板列表页 & 我的应用页

| 项目 | 说明 |
|------|------|
| 文档版本 | v1.0 |
| 对应原型 | `mall-prototype/index.html`（`#page-templates`、`#page-mall-list`）及相关逻辑 `app.js`、`data.js` |
| 范围说明 | 仅覆盖侧栏「模板列表」「我的应用」两页；不含可视化编辑器、电影票等其它页面 |

---

## 1. 背景与目标

### 1.1 背景

运营人员在「商城端」工作台需要：

1. 在**模板列表**中查看平台已上架模板，按需筛选、搜索，并进入后续使用流程（原型为打开编辑器）。
2. 在**我的应用**中管理基于模板创建的商城应用，控制**线上对外可见的已发布实例**（业务上需保证互斥规则）。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| G1 | 运营可快速找到符合标签/关键词的可用模板。 |
| G2 | 运营可总览本人或本租户下的应用，识别草稿与已发布状态，并安全完成发布。 |
| G3 | 关键操作（如发布应用）具备明确二次确认，避免误操作。 |

---

## 2. 角色与入口

| 角色 | 原型表现 | 权限假设 |
|------|----------|----------|
| 平台运营 | 侧栏底部展示 `运营账号：ops@platform.com` | 可访问两页数据、执行搜索、从模板进入编辑、发布应用（实作需对接登录与租户/数据权限） |

**导航**：侧栏「模板列表」→ `data-page="templates"`；「我的应用」→ `data-page="mall-list"`。点击后切换主区 `section` 显隐，仅一页处于激活态。

## 3. 模板列表页

**页面 ID**：`#page-templates`  
**默认进入**：工作台打开时默认展示本页（`active`）。

### 3.1 页面结构

| 区域 | 说明 |
|------|------|
| 页头 | 标题文案：`模板列表`。 |
| 筛选区 | 左侧：标签下拉；右侧：名称搜索框、搜索按钮、重置按钮。 |
| 说明条 | `/` 下方提示：`以下为已发布的模板，可直接选择使用`。 |
| 内容区 | 模板卡片网格容器 `template-tbody`。 |
| 分页区 | 容器 `template-pagination`。 |

### 3.2 数据范围与展示规则

| 规则 ID | 描述 |
|---------|------|
| T-LIST-01 | 列表数据来源为**模板库**；仅展示状态为**已发布**（`published`）的模板；**草稿**模板不出现在本列表。 |
| T-LIST-02 | 展示字段：模板名称、标签、最近修改时间、封面图（原型为按标签生成 SVG 示意首页）。 |

### 3.3 标签筛选

| 控件 | 说明 |
|------|------|
| 控件 ID | `filter-tag` |
| 选项 | 全部、美妆、食品、服饰、618大促 |
| 行为 | 选「全部」不按标签过滤；否则只保留 `tags` **包含**所选标签的模板。 |
| 触发 | `change` 即重新过滤并重置到第一页。 |

### 3.4 名称搜索

| 项 | 说明 |
|----|------|
| 占位 | `搜索模板名称...` |
| 触发 | 点击「搜索」或输入框内按 **Enter**。 |
| 逻辑 | 去除首尾空白后，对模板名称做**不区分大小写**的子串匹配；与当前标签筛选**同时生效**。 |
| 空结果 | 内容区展示「暂无符合条件的模板」。 |

### 3.5 重置

清空标签为「全部」、清空搜索框与内部关键词状态，重新拉取当前条件下的列表（原型为前端重算）并回到第一页。

### 3.6 分页

| 项 | 说明 |
|----|------|
| 方式 | 前端分页。 |
| 每页条数 | 5。 |
| 展示 | 总条数文案、`上一页`、页码按钮、`下一页`；首页禁用上一页，末页禁用下一页。 |
| 联动 | 筛选或搜索变化时重置当前页为 **1**。 |

### 3.7 单卡操作

| 按钮 | 行为（产品要求） | 原型行为 |
|------|------------------|----------|
| 预览 | 用户可查看该模板在真机/预览环境的渲染效果 | 弹出提示，说明真实系统可新开窗口预览 URL |
| 使用 | 进入模板配置/编辑流程；在编辑页完成编辑后，点击「保存」或「发布」，系统需将该模板生成一条应用记录并保存到「我的应用」页面（发布时同时遵循「仅一个应用已发布」规则）。 | 新开 `editor.html`，URL 查询参数包含模板 `id` 与 `name` |

### 3.8 与「我的应用」的关系

本页不直接创建应用；「使用」进入编辑器后，编辑器侧可通过业务逻辑生成「我的应用」记录（见 `app.js` 中 `addMallFromTemplate`，不在本文展开）。

## 4. 我的应用页

**页面 ID**：`#page-mall-list`。

### 4.1 页面结构

| 区域 | 说明 |
|------|------|
| 页头 | 标题：`我的应用`；主操作：`+ 新建商城`（`btn-new-mall`）。 |
| 工具栏 | 单行搜索：商城名称或品牌；「搜索」按钮。 |
| 说明条 | `应用基于模板创建：仅一个应用处于「已发布」，其余为「草稿」`。 |
| 内容区 | 应用卡片网格 `app-tbody`。 |
| 分页区 | `mall-list-pagination`（原型为总条数汇总，无多页码）。 |

### 4.2 数据字段（单条应用）

与 `MOCK_MALLS` 对齐，落地时需持久化：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 应用唯一标识。 |
| name | string | 应用/商城名称。 |
| brandName | string | 关联品牌展示名。 |
| templateId | string | 关联的模板 ID。 |
| status | enum | `draft`（草稿） / `published`（已发布）。 |
| createdAt | string | 创建时间展示。 |

**展示衍生**：卡片封面、标签继承关联模板（`MOCK_TEMPLATES` 中对应 `tags`）；。

### 4.3 核心业务规则

| 规则 ID | 描述 |
|---------|------|
| A-RULE-01 | **同一时间维度内（原型为当前列表数据集，产品上建议为同一租户/同一运营主体）最多允许 1 条应用为 `published`。** |
| A-RULE-02 | 将某应用发布为已发布时，须先把**其它已发布应用**全部置为 `draft`，再置当前为 `published`。 |
| A-RULE-03 | 已是 `published` 的应用，其「发布」按钮不可用或展示为「已发布」，避免重复提交。 |

### 4.4 搜索

| 项 | 说明 |
|----|------|
| 占位 | `搜索应用名称...` |
| 触发 | 点击「搜索」或输入框 **Enter**。 |
| 逻辑 | 对 `name`、`brandName` 做不区分大小写的子串匹配；可两端空白。 |
| 空结果 | 展示「暂无应用」。 |

### 4.5 新建商城

| 项 | 说明 |
|----|------|
| 触发 | 点击「+ 新建商城」。 |
| 原型 | 提示占位，不落地创建。 |
| 产品建议 | 跳转创建向导或弹窗：填写应用名称、选择模板、绑定品牌等，保存后回到列表。 |

### 4.6 单卡操作

| 按钮 | 条件 | 行为（产品） | 原型 |
|------|------|--------------|------|
| 预览 | 始终 | 查看当前应用关联模板的预览 | 弹窗提示 |
| 编辑 | 始终 | 进入配置/编辑 | 以 `templateId` 打开 `editor.html` |
| 发布 | `status === draft` | 弹出二次确认后执行发布规则 A-RULE-01～02 | 弹窗确认后更新内存数据并刷新列表 |
| 删除 | `status === draft` | 点击后弹出二次确认，提示文案：`确定要删除这个草稿吗？`；确认后删除该草稿应用并刷新列表，取消则不做变更。 | 删除功能 |
| 已发布 | `status === published` | 仅展示状态，不可再次发布 | 按钮 disabled，文案「已发布」 |

### 4.7 发布二次确认（弹窗）

**元素**：`#modal-publish-app-step1`。

| 项 | 内容 |
|----|------|
| 标题 | `确认发布` |
| 正文 | 确定将该应用设为「已发布」吗？**其他已发布应用会变为「草稿」。** |
| 主按钮 | 确定发布 → 关闭弹窗并执行发布逻辑。 |
| 取消 | 关闭弹窗，不修改数据。 |
| 关闭图标 | 同取消。 |

该弹窗属于「我的应用」发布路径的必要环节，应在最终实现中保留。

### 4.8 分页/统计（原型）

当前实现为列表过滤后展示「共 N 条」；若数据量大，建议与后端分页参数对齐（page、pageSize），并保持与搜索条件同步。

## 5. 非功能与体验

| 类别 | 要求 |
|------|------|
| 反馈 | 列表加载中/失败需有 loading 与错误提示（原型无）。 |
| 审计 | 应用发布记录操作人、时间、应用 ID（原型无）。 |
| 无障碍 | 主要按钮与弹窗支持键盘与 `aria`（原型部分具备 `aria-label`）。 |

---

## 6. 验收要点（建议）

| 编号 | 场景 | 期望结果 |
|------|------|----------|
| AC-01 | 模板列表仅标签「食品」 | 仅展示 `tags` 含「食品」且状态为已发布的模板。 |
| AC-02 | 模板列表搜索不存在的关键字 | 空态提示。 |
| AC-03 | 模板列表翻页 | 每页最多 5 条，总条数与页码正确。 |
| AC-04 | 我的应用搜索品牌关键字 | 匹配 `brandName` 的应用展示，其余不展示。 |
| AC-05 | 草稿应用点击发布并确认 | 该应用变已发布，原已发布应用全部变草稿，且仅一条已发布。 |
| AC-06 | 已发布应用 | 发布按钮不可用，文案「已发布」。 |
